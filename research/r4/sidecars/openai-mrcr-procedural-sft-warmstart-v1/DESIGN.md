# Short-MRCR procedural SFT warm-start

Status: CPU teacher construction only; no GPU launch or optimizer command is authorized.

## Question

Can a small, explicit root-procedure SFT dose teach the 4B controller to recover the requested
assistant response from ordered conversation JSON, rather than merely changing a cold policy or
adding a target-bearing preview?

## Frozen data and teacher

Use all32 `train` records in `openai-mrcr-short-root-data-v1/MODEL_INPUTS_V2.json`; do not read or
query the16 `heldout` records during construction, dose selection, or checkpoint selection. Every
teacher is generated by one unchanged rule:

1. Parse the public question grammar into its public marker, ordinal, response kind, and topic.
2. Form the public request string `write a {kind} about {topic}`.
3. In `/context.json`, preserve message order, find user messages whose complete stripped,
   case-folded content equals that request, require a following assistant record, take the requested
   ordinal, and print `marker + assistant_content`.

The action contains those public constants, never a hidden message index or copied answer. Host gold
is consulted only after construction to audit exactness and later supplies the legitimate supervised
terminal target. Every attempted teacher and failure remains in `TEACHER_AUDIT.json`; there is no
silent filtering or case-specific repair. A failure blocks the all32 corpus and requires a separately
predefined filtering decision.

## Rendering and proposed fixed dose

Render the exact short32 system/user/tool ABI using Qwen3-4B-Instruct-2507 with thinking enabled.
Each example has two root targets: the complete IPython tool-call suffix, then the exact terminal
response after the authentic deterministic tool observation. Prompt, tool observation, environment,
and any child tokens are masked. Action and terminal token counts/objectives remain separate.

Conditional on MAIN review, the thinnest trainer reuses
`root-complete-demonstration-sft-v1/learning.py`: fresh zero-init rank8 LoRA from the unadapted 4B,
fresh AdamW, LR1e-4, weight decay0, clip1, seed2026091401, four full32-example passes, action mass1.0
and terminal mass0.1, checkpoint every pass, fixed checkpoint4. No validation selection and no RL.
Abort before mutation on corpus/hash/mask/sequence failures. Save adapter, optimizer, RNG, state, and
root-only binding; child remains the frozen unadapted4B.

The later scientific endpoint is predeclared but not yet opened: base4B versus fixed checkpoint4 on
all16 heldout records, two fixed repeats each, identical raw JSON/harness/seeds, exact official score
primary, C/W/U and procedure diagnostics separate. It is held out from this project update and
selection, not from base-model pretraining. Training-set exactness is a manipulation check, not a
generalization claim.

## Promotion and stopping

- Proceed to training only if the generic program is32/32 official-exact, the stored first prefix
  equals the authentic short32 prefix, all action/terminal masks are exact, and every sequence is at
  most8192 tokens.
- Promote to the heldout endpoint only after four finite optimizer commits and a functional train-only
  readout showing at least8/32 exact with at least4 contexts represented. This gate concerns whether
  the intervention took effect, not model selection among checkpoints.
- Retire this recipe if checkpoint4 has fewer than8/32 train exact or introduces integrity/ABI
  failures. Do not tune on heldout or silently retain only successful teacher trajectories.

Measured precedent: the reused trainer completed four passes over16 two-turn demonstrations in49 s
for action-only and81 s for action+terminal, with about11.2 GB peak allocation. The longer terminal
targets here make a 2–4 minute optimizer stage plausible, not guaranteed; cap the future train owner
at600 s. Two final 32-episode evaluation arms likely make total GPU wall time12–20 minutes.
