# Does grouping public rows help before resolving them?

On twelve new fixed stages, compare the original relational tables, a candidate-grouped but fully
unresolved view, and the previously tested resolved effective-record view. Every candidate and every
public base, change, and check row is retained. The unresolved view performs no delta arithmetic,
feature update, latest-check choice, filtering, or eligibility decision. The model, seeds, output
contract, and per-answer call count are fixed; wording and input length are not token-matched.

This separates some presentation/locality benefit from mechanical state resolution. It does not
isolate every wording effect, demonstrate learned decomposition, or consult host labels in prompts.
