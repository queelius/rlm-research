# Query-sensitive root RL: two options, design only

Current status: MAIN approved CPU implementation of Option A in this sidecar. The original design-only language and Option B below are preserved proposal history, not a restriction on the subsequently approved CPU work and not approval to launch. MAIN alone retains GPU acceptance/launch authority.

Recommendation: Option A, a four-hour free-start operator/composition pilot. Do not revive the retired whole-context-count curriculum, select a joint-SFT checkpoint from test outcomes, or bundle state-start mixing into this first operator test. No implementation or launch is authorized by this memo.

## Why this question

Completed BROAD16 improved 13/48 to 16/48 but left its composition panel 5/24 unchanged. The later low66c bounded-RL study improved 7/24 to 11/24 while query transfer stayed 0/8; much of its gain was length/format. Corrective SFT's completed controlled arm obtained five correct/16 but only one authenticated faithful scalar reduction, with four successes after reacquisition. This argues for executed query-sensitive success, not more copied-map targets, CE reduction or nominal optimizer steps.

Current joint SFT metadata shows both fixed-four arms completed training from low66c: joint 288 root-turn exposures/20,064 target-token exposures, reduction-stop 128/5,024. The balanced-four forward gate had nonliteral reduction-code NLL 1.52–2.81, while terminal NLL was near zero. This establishes objective headroom and execution, not free-policy competence. This memo has not inspected its held-out readout or selected any checkpoint. Its pending scientific result can change whether MAIN launches this proposal, not the proposed starting checkpoint.

## A — Recommended: learn operators from free starts

**Falsifiable question:** can root-only terminal-reward RL improve free autoregressive success on operator × scope combinations absent from training, on group-disjoint records? Baseline is unchanged low66c; trained policy is its last actually committed RL checkpoint. Frozen c32 child and the accurate typed-ID interface are identical. This estimates the effect of the training package, not the isolated benefit of operator breadth versus count-only RL.

Each public record has `id`, `user`, `text`, and positive integer `weight`. IDs, four balanced user identities and weights 1–7 are deterministically assigned independently of gold labels. User/weight assignments vary across contexts. All classification labels are inferred by the models; the data files contain no categories. Six standard label definitions and the helper's truthful argument/return contract are common to all tasks/policies. No demonstrated algorithm, aggregation helper, recursion requirement, gold map, scalar fallback, or example solution. Children return actual c32 predictions; wrong labels, missing coverage and failed calls are retained. Root may classify directly or call children.

The question names one target class, a user scope, and one integer-valued operator in ordinary semantic language. A union is a set of users: each record is eligible once. Weighted sums use visible record weights, not user weights; distinct-user count counts users with at least one qualifying record. The answer remains the same strict whole-response `Answer: N` contract.

| Operator | Singleton user | Two-user union | All four users |
|---|---|---|---|
| Count qualifying records | Train | **Held out** | Train |
| Count distinct qualifying users | Train | Train | **Held out** |
| Sum weights of qualifying records | **Held out** | Train | Train |

This is genuinely different computation, not category substitution. Singleton distinct-user training is an existence test (0/1); transfer to all users tests a nontrivial composition and is not claimed to identify a general set algorithm. Scopes/targets are not chosen using model success or gold answer magnitude. Report zero-answer prevalence and accidental equality between different queries; do not discard these coordinates or silently rebalance them after seeing outcomes.

**Small fixed curriculum:** 12 training contexts × 16 records; one fixed window per context, with three questions (one per operator), eight sampled roots each: 12 scheduled windows, 36 task groups, 288 attempted slots. The two trained scopes for each operator are balanced across the 12 contexts. Four common targets HUM/ENTY/LOC/NUM each occur in three contexts; the same class within a context lets different questions require different reductions of the same records. Scope/target/task order and fresh seeds freeze before launch. There is no refill, forced recursion, curriculum adaptation or reward shaping.

**Reward and objective:** reward 1 only for an authenticated actual native final whose strict integer equals the host-computed dataset answer; verified returned wrong/malformed/wrong-route responses score 0. Missing transport, unreturned endpoints and unverifiable branches remain NULL. Available endpoint does not imply training admission: preserve the qualified stricter complete-graph/token/logprob admission and mixed-within-task rule. No-final tool loops are not fabricated sampled wrong answers; report them as operational failures with a separate planned-denominator zero sensitivity. Use unchanged qualified TIS/PPO numerical objective, equal-episode/turn/action-token weighting, LR 5e-5 and root-only masks. Observations, prior actions and child tokens are masked. A homogeneous or fully unadmitted window advances only the window cursor, not Adam. Fewer informative updates is evidence, not permission to reroll.

**Mandatory paired readout:** 12 disjoint contexts (eight × 16 records, four × 32), four questions each: the three held-out cells plus one supported cell, balanced over the six supported cells. Exactly 48 inputs × unchanged/trained = 96 free endpoints, paired fresh seeds, same native prompt and sampling settings across policies. Report 36 held-out and 12 supported pairs separately, then 16/32-record strata. The 32-record stratum combines new operator/scope and length; do not attribute its difference solely to operator transfer. Contexts, not 96 rows, are the highest independent sampling units. Primary results: strict executed accuracy, NULL bounds, paired wins/losses, planned-denominator operational success. Secondary: format, actually executed scope/reduction/stop behavior, map coverage/label quality, reacquisition/loops, physical root/child calls and tokens. Map agreement or prompt/AST mentions alone do not authenticate use.

No best-checkpoint readout or GPU validation is needed. All 288 training and 96 readout slots are planned before launch; training signal is reported from its fixed groups. Final both-policy readout occurs even if learning stops early or yields zero updates. Fixed declared policy order has a time-order limitation.

**Four-hour inclusive envelope:** outer 14,400 s = work 14,100 + owned cleanup 180 + outer margin 120. Within work, at most 9,000 s for training-side startup/collection/optimization/checkpoint/release; protect the remaining 5,100 s for both final-policy blocks (2,550 each, including service lifecycle). Four rollout workers, 8,192 context and 2,048 per-call sampling cap, temperature 0.5; 180 s endpoint cap. Stage caps nest inside absolute deadlines rather than adding extra time. Stop starting learning work before it would consume final reserve. Exact transition-time guards need implementation review, not a promise that all 12 windows fit. Historical 64-episode/four-update RL plus 48 readouts took 2,127 s; BROAD16's 384 attempts plus validation/transfer took 8,083 s. These support feasibility, not a throughput guarantee on new tasks.

Checkpoint every actual update: adapter, persistent Adam moments, RNG, actual optimizer cursor, candidate-window cursor and consumed native-input hashes. Commit the no-op window ledger too. Preserve partial window attempts; no automatic replay, refill or duplicate step. Restart requires a separately accepted continuation bound to the last commit and original cumulative debit; it cannot reset the four-hour budget or final reserve.

Remaining authenticated TREC groups: train 526, validation 12, test 393. Option A needs only 448 train-partition groups (192 training + 256 readout), leaving 78. Exact file hashes and scope are in `operations/2026-09-09-allocation-5780/query-sensitive-source-availability.json`. No new contexts have been selected yet.

These can be new to the checked root/prepared inventories and disjoint across train/readout, but are all child-SFT-training-exposed. Outside named manifests, paraphrases, model pretraining and unindexed historical use remain unknown. Freeze and recheck named exclusion manifests at dataset preparation; if availability shrinks, report the conflict rather than silently reuse old data. The retired broader proposal had reused 47 context byte strings and 80 questions; this design does neither by intent. Group novelty is secondary to the new operator/scope tasks, not a claim of a pristine benchmark.

## B — Alternative: isolate state-start density, not operator breadth

Fix one task family (user/union-scoped record count), a common new-context split, low66c/c32, and compare **free-only RL** against **50% free / 25% genuine half-acquired / 25% genuine fully acquired starts**. Use eight fixed windows per arm, two task groups × eight episodes/window: 128 slots/arm, 256 total. Keep the question/seed/task schedule paired where meaningful, but recognize that changed initial histories prevent token-identical training pairs. Actual authored acquisition runs execute c32 in the same native REPL; no correction/scalar/final is in the prefix. Store the genuine prefix and state; mask acquisition actions/observations, credit sampled continuation only. Never substitute dataset labels for wrong child predictions.

Mandatory evaluation is free starts for unchanged/free-trained/mix-trained, 24 paired questions per policy = 72 endpoints, plus 24 balanced conditional diagnostic endpoints. Charge actual capture once physically and full acquisition per hypothetical standalone episode; equal episode count is not equal compute or trainable-token exposure. Four-hour ceiling includes capture, both arms and readouts, making fewer actual updates more likely. This is a harder runtime seam than A, and a result could reflect easier terminal reward/state exposure without improved free reachability. It is useful if joint SFT exposes a persistent gap between conditional finishing and free control, but it is not an operator-breadth test.

## Decision and minimal implementation boundary

Choose A first: distinct held-out combinations, unchanged baseline and a real free-policy test directly address the failure left by prior RL. B is a separately frozen alternative, not an extra factor slipped into A. If A produces few informative updates or no held-out gain, retain that result and propose a separate budget/state-start experiment; do not redefine its task distribution during the run.

Minimal new code after approval: deterministic records/query/gold/split builder; native task binding that tests operator/scope conditioning and absence of host gold; thin collector/planner over the working an27 runtime; fixed-window coordinator and checkpoint cursor seam over the qualified bounded-RL trainer; native endpoint ledger and paired scorer. Reuse numerical training and service lifecycle unchanged. Focus CPU checks on actual native prompt/task semantics, exact host operator truth tables, disjoint sources, deterministic schedules/NULL plans, cursor/resume admission and the actual owner → service/config/descriptor → intercepted Popen entry path. No broad framework, new driver compatibility paths, services, GPU calls or queue edits were made for this design.

## Implementation approval

MAIN approved Option A only. This sidecar implements 12 free-start windows / 288 training slots and 96 final paired endpoints, never Option B. Selection uses the pinned 53-manifest exclusion receipt; public id/user/text/weight are common to both policies. Report zero and best-constant host baselines and cross-query answer coincidences without selection. Equal episodes are not equal tokens or FLOPs. No GPU validation or current-SFT-test-based change.
