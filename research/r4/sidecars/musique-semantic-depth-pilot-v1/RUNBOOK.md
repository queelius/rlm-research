# Fixed MuSiQue semantic-depth feasibility pilot

Question: does allowing optional child/grandchild reasoning help this fixed pretrained 4B model answer semantic multi-hop questions at the same actual call budget? This tests a runtime intervention, not learned recursion or a new decomposition algorithm. MuSiQue already includes decomposition-based approaches.

Frozen inputs: twelve MuSiQue-Ans v1.0 development questions, four each at 2/3/4 hops, selected by full-row SHA rank in the approved namespace. Duplicate normalized questions, reused single-hop IDs and exact supporting paragraphs are excluded within the selected twelve. This uses host structural metadata, not observed model outcomes or answers. The manifest preserves source IDs, raw-line/canonical hashes, overlap memberships, token lengths and provenance; source IDs and hop/decomposition/support annotations are not placed in prompts. Original paragraphs, titles, ordering and question are preserved. Public cache acquisition is pinned to official repository commit `922ac98f19a201998dbdae6d7f2887a5258dbdeb`, archive SHA `98f839bf2fd5319f5c688aed77901a6d5c30b3b9f9f691ab9a8ecafb045ee0cd`, CC-BY-4.0 attribution. Base-pretraining exposure and semantic overlap are unknown.

There are 48 episodes: twelve each at maximum depths 0, 1 and 2, plus twelve one-call question-only diagnostics. All primary arms see the same external `/context.json`, root wording, pretrained Qwen3-4B weights, per-question seed and temperature .5. Depth zero remains a Python RLM without children, not a conventional direct-answer baseline. The question-only arm sees no paragraphs/tools, is not cost-matched, and never filters the primary set. Root and children share one base model with no research adapter; no compulsory delegation, retrieved oracle passages, intermediate answer hints or host answer program are added. Host gold is mode0600 and not staged into the runtime. The runtime document is instructed as input data; filesystem immutability inside each ephemeral container is not claimed.

The physical cap is six root+child+grandchild requests per primary episode (one for question-only), at most1024 generated tokens each, and actual rendered prompt length+1024 must be at most8192. A synchronous coordinate-level reservation before any await also counts inflight requests; it supplements the framework's completed-turn counter. An overlong prompt is refused before transport, not truncated. `RLMHarness.max_depth` is the unchanged nano runtime depth policy. The actual CPU fixture traverses root→child→grandchild, tests absence of recursion at the leaf, exact six-response causal mapping, seventh-call refusal, question-only native decoding and actual overlong refusal. No weights/GPU are loaded in that fixture.

Schedule is fixed, with arm order rotated by question and a shared FIFO of four workers. Per-episode deadline180 seconds, science1320, startup≤240, cleanup reserve90, owner1700, external1800. Owner startup consumes wall budget; completion is not guaranteed. Request/response raw UTF-8 bodies (no secret headers), typed tokens/logprobs, pending-turn provenance and per-episode raw traces are checkpointed exclusively, with no retries/resume. A cap or failure does not authorize extra examples, alternate models or a changed deadline. Total planned upper bound is228 physical calls and233472 generated tokens. `CORRECTION.md` fixes the original timing-reference attribution without changing the sealed proposal.

Scoring requires whole-response JSON `{"answer":"...","support_idxs":[...]}` with exact keys, no duplicate keys/indices and valid integer indices. No fence/prose extraction or repair. Official MuSiQue alias-max normalized answer EM/F1 and paragraph-support EM/F1 are unchanged. A completed malformed final is an observed model failure with zero metrics; unknown framework stop/error or unavailable native mapping is U, never silently wrong. Clean authenticated finite-horizon caps are W/zero. Guard refusals that leave an ambiguous/error trace remain U with an explicit refusal category. All arms retain planned denominator12; available-only means are labelled. Missingness blocks promotion, and unknown error-call usage remains an unknown count beside observed token subtotals.

Primary comparison is depth2−depth0; depth1 is a prespecified mechanism readout. Screen for a fresh replication only: all48 available, net primary EM wins≥2, mean answer-F1 gain≥.05, support-F1 nondecrease and EM gains in at least two hop strata. Report every arm regardless. No grandchild use permits only interface/behavior-feasibility conclusions, not that depth2 is ineffective (or that a gain demonstrates deeper reasoning). Twelve clusters do not support a confirmatory claim; report physical calls, output/input tokens, depths, support accuracy, malformed/unknown categories and fixed-deadline partial tails.
