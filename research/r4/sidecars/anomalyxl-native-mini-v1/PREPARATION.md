# Bounded native AnomalyXL mini-pilot

Twenty episodes, ten metadata-only frozen cases, no training. MAIN alone launches the READY owner under the shared GPU flock and an external 1,200-second timeout; the owner has 1,100 seconds including service startup and cleanup. It uses one fresh exact cached Qwen3.5-4B service, temperature 0, eager BF16, no adapters, native token transport, and batch-invariant flag 0. This is a new runtime and cannot be pooled with earlier c32/flag-1 counts. Loopback-only service configuration contains no API key.

The first two calls are engineering-only: generated Python must actually read a staged synthetic public file and compute 6, then the native final response must be exactly the requested JSON. Both must terminate with `stop`; no research episode starts if either fails. Registration and CPU configuration validation do not prove live Qwen3.5 serving. No model substitution, API fallback, retry or install is permitted. CPU preparation found SciPy absent in the existing native environment: prompts explicitly permit installed NumPy/stdlib, and the real worker fixture verifies NumPy arithmetic. No cross-environment numerical-library graft was added.

The direct arm sees every channel at fixed uniform strides retaining original indices, at most 6,144 actual template tokens plus 2,048 output tokens. The Python arm sees the same question and full 3-decimal public numerical arrays through the current process-isolated IPython executor. Successful trajectories use three strict fenced-code inspections then one final-only response. Each inspection gets at most 512 generated tokens; final gets the remaining aggregate 2,048-token budget, not a fixed 512. Whole rendered observations are at most 2,048 characters; full execution results remain on disk. Every call checks actual prompt plus requested output against 8,192. The 45-second episode deadline bounds work requests; worker cleanup follows through the existing bounded executor cleanup path.

The official standalone `score_precise` file was read completely before import. Its original balanced-JSON extraction is retained unchanged: extractable JSON inside prose may earn its official score. Whole-response strict JSON is reported separately, never used to silently zero or repair official results. This explicitly overrides the earlier proposal's inaccurate “invalid JSON zero” shorthand. An absent answer scores as the official empty-string result, with failed/unattempted status retained. Fixed denominator is ten pairs, but a full-panel readout is eligible only after all twenty episodes and qualified release. An engineering failure has no paired primary mean.

Raw native request/response bytes, messages, completion token IDs, model/request identities, finish reason and observed/cache/unknown usage are checkpointed per physical call. Public workspaces contain no gold; host gold is first loaded by the owner after service release for scoring. Every episode retains code, bounded observations, execution errors, answer, generated tokens and elapsed time. RESULT reports direct/Python/research/engineering costs separately. Credential-like environment variables are removed from workers and service. The worker is not a filesystem or security sandbox; no stronger isolation claim is made.

The official paper disables recursive sub-RLM calls and studies iterative Python inspection. This pilot likewise has no children. It neither reproduces the paper's 300-step fresh-generator, group-8 full-parameter RL nor learns tree depth. Direct subsampling versus full-data Python intentionally changes information access. Ten exposed synthetic cases assess feasibility and continuous-score headroom, not broad superiority, novelty, population accuracy or an RL gain. Both-arm floors call for failure inspection or deferral; no automatic RL follows.

Exact files: mini.py owns public preparation, tokenizer/native decode, official scoring and the current executor seams; native_service.py owns only this new local service; owner.py owns the fixed schedule and terminal accounting; seal.py freezes inputs and full source/model/data closure. Two focused fixtures exercise the real CPU executor/credential scrub, native token/context/budget behavior, observation cap and native config, then official-score parsing and metadata-only inventory. Prior closures and environments are untouched.
