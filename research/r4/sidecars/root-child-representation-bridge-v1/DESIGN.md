# Same-map-API scalar bridge32

Implement MAIN's approved checksum amendment, not the superseded first-match task.
Four fixed exposed development contexts: query_transfer-00/01 (32 records each),
length_transfer-00/01 (128 each). Two tasks globally use each context's already-public
target category: count and sum numeric source-ID suffixes. Two fresh seeds; array/map
child representation; 32 physical episodes, 16 pairs, four context clusters. Primary
checksum map-minus-array; count separately. No pooled primary, historical pooling or
post-observation checkpoint/context choice. Fixed low-SFT8 root66cce and childc32.

Root prompt, familiar first-four API example, public files, weights, sampling and
allowed actions are equal within task pairs. We reuse the frozen global prompt
template, substituting only the public record count and the final question. The
query-transfer historical package did not contain global queries; this is explicitly
a new whole-task package, not a data-only historical comparison. Source labels and
count/checksum gold stay host-only. Public metadata is retained but scope is global.

The supervisor authenticates exact original request_for(public ID/text records),
root invocation and child depth1. It changes the child output instruction consistently
with array versus object schema before engine.run. The trusted native role hook independently
round-trips that actual request against the host catalog and applies one ordered grammar
decision per ordinary depth1 invocation. Altered text, unknown/repeated IDs, custom
vocabularies or requests, root calls and deeper children remain untreated. Tools remain
listed, but grammar restricts eligible children's effective output action space from
their first response. This is not harmless formatting or an attention probe.

The actual child result, raw tokens, log probabilities and graph remain untouched.
Only a new broker return object replaces answer with canonical source-ordered map JSON:
an array is zipped in requested order, an object is strictly parsed/reordered. Raw
malformed returns pass through unchanged, visibly failing the same public strict_map;
semantic misclassifications are never repaired. Matching maps themselves contain
grammar-provided source IDs, not freely retrieved IDs. Both arms log invocation,
raw result and successful broker delivery; root-writable logs are claims, corroborated
against trusted native invocations, original/actual requests and later root input.

No sampled plans are forced. Any direct root solution is valid. Report actual requested
widths 1–4, 5–16, 17–64, >64 and qualifying pair uptake. Fewer than eight paired episodes
with eligible calls is limited exposure. Strong component effects at64 do not establish
an effect at16; existing accurate 16-wide maps lack an array control. Checksum arithmetic
and subset-sum collisions can hide child improvements. Separate schema validity, semantic
record correctness, unique coverage/conflicts and evidence-to-scalar fidelity from task
accuracy. Delivered unions are not necessarily the final physical branch or proof that
the root consumed every map. Raw graphs permit an independent final-branch audit.

Strict endpoint is whole stripped ASCII `Answer: [0-9]+`; observed empty/malformed/wrong
is0; incomplete/unavailable isNULL. Retain all32 slots, stage/episode/finalization errors,
native attempted and returned calls, full IDs/logprobs, cached/uncached usage from raw
wire JSON body, all costs including failures. Seeds reduce variance, not deterministic
counterfactuals; record initial root token/output equality and first eligible invocation.
