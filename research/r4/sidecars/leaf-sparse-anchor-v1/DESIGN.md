# Sparse identity anchors: bounded component tradeoff

Approved by main on 2026-09-09 after independent AG96 and cue48 results. No GPU or service authority is delegated to the preparation agent.

Question: do periodic matching source-ID anchors retain useful displayed-record accuracy while reducing output tokens? Primary is matching-minus-constant within each cadence and task. Across cadence, accuracy versus actual completion tokens is a representation-and-cost tradeoff, not a pure attention intervention or a fixed-compute comparison.

Population: the four exact 64-record TREC and four SST2 contexts in `leaf-identity-factorial-v1/SPEC.json`, plus all four AG contexts in `leaf-identity-agnews-weight-v1/SPEC.json`; first prior presentation, disjoint q source IDs, unchanged full text and host gold. Select by context index only, never by previous outcomes. All contexts are exposed. Each task has four context units; two seeds and three cadences/two tag rules are nested repeats, not independent data. AG is task transfer, not a relabeled TREC/SST benchmark. Retain pinned public source revisions/licenses, with AG license unknown and pretraining exposure unknown.

Anchors are displayed positions 1,1+k,… (64/16/4 anchors). At anchors emit `{"tag":"…","label":"…"}` with that exact key order; elsewhere emit a bare canonical JSON label string. Matching tags equal the corresponding source q ID; constant tags are `p0000`. Both arms use the same 64-item shape within cadence; cross-cadence shape intentionally changes. All 64 labels contribute to the score, including anchors. The first item is not an independent control.
