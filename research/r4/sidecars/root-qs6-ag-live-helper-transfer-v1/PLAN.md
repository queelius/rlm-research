# Frozen-root, live-helper AG transfer

Approved CPU preparation only; MAIN alone reviews and launches. The question is whether the
fixed original broader RL8 helper improves final aggregation under an unchanged QS6 root,
relative to c32 and an accurately named no-child/Python RLM control. This is fresh article
content with familiar operators, not new-operator generalization or a learned planner.

1. Implement and CPU-qualify a new isolated sidecar. Freeze 128 outcome-blind official AG test
   articles as eight label-blind groups of 16, excluding every canonical local exposure and
   the new official512 panel. Use two fixed queries/context (count, weight sum), rotating all
   four labels twice/family. No within-context class balancing or answer-based resampling.
   All 48 episodes use the same QS6 root, paired root seeds and common caps. The two helper
   arms have byte-identical root prompts. A full16 exact serialization request invokes four
   live canonical B4 calls; it only merges returned keys and never sees gold or the question.
   No saved prediction map, retries, fallback labels, root training, or question-to-code solver.
   Reuse the accepted evidence-V2 native task/runtime and the short32-V2 trace mapping seams;
   do not revive the unqualified headroom owner. New files: study.py, protocol.py, prepare.py,
   live_helper.py, collect.py, owner.py, metrics.py, test_transfer.py, seal.py, RUNBOOK.md,
   frozen inputs and READY. Keep all existing closures untouched.
2. MAIN reviews exact closure, actual serialized-input/ordered-label/host-gold separation
   fixture, runtime/endpoint qualification and complete missingness/cost accounting, then
   decides launch. No GPU authority is implied by data or source readiness. Fixed original
   RL seed1 checkpoint8 is selected by prior plan, not by comparing seeds. Runtime owns two
   sequential services because its existing maximum is two simultaneous LoRAs: QS6+c32 for
   control/c32, then QS6+RL8. Record this scheduling/cache-history limitation explicitly.

Public runtime files contain only id, user, original text, positive integer weight, exact
question and pure serialization/validation code. Host gold stays separate mode0600. Preserve
all raw physical requests/responses, wrapper-vs-physical accounting and root trace tokens.
Final accuracy, helper label accuracy and consistency with the helper-derived aggregate are
separate outcomes. Missing infrastructure never becomes a semantic zero. Every episode and
native call checkpoints immediately; finite-horizon model failure and malformed output are
reported separately. Ledger/input-budget followups require an observed error pattern.
