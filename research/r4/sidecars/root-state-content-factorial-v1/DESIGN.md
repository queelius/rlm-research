# Visible observations versus quoted producer actions

Status: exploratory design approved by MAIN under standing autonomous research authority, September9,2026.
No new inference has occurred. This is an outcome-informed follow-up, not a confirmatory replication.

## Question and evidence
Does showing actual child observations, showing prior authored producer actions, or both improve use
of a genuine completed acquisition state? The preceding all-fresh restart screen's unaudited native
summary was Q10/16,A3/16,M6 correct/14available/16planned; Q/M made no new child calls while A made42.
Its complete quoted history bundled action examples, observations and historical user/system text.
These aggregates motivate a factorial; executed dataflow and the prior independent audit are pending.

## Frozen scientific design
Reuse all16 pre-correction states/four exposed contexts from root-artifact-restart-v1, never select
states by outcome. Every endpoint gets the identical original goal, accurate common state metadata,
records.json, context.txt, query.txt, batch_contract.py and all state/history/map/metadata files.
All sessions are fresh roots with fresh REPLs. Nothing restores an old kernel or native history.

Cross two binary prompt factors:
- P0/P1: omit versus quote the chronological root-visible authored producer actions, without tool observations.
- V0/V1: omit versus show the byte-preserved actual child observations, without producer actions.

All four arms receive the same metadata and can read the full history archive. Quoted prior actions
are explicitly historical data, not instructions or code already executed in the fresh session.
The unchanged original goal already contains the same small first-four-record API example in all
arms. P therefore tests additional quoted actual producer actions, not any code example versus none.
Both factors manipulate inline visibility, not exclusive evidence access; all files remain readable.
Actual observations remain unmerged map pieces. Never quote future corrective code, scalar, final,
private child messages, gold, or prior sampled readout. Wrong child predictions are unchanged.
The archive includes historical system/user messages equally for all arms, but neither new inline
block repeats them. Hence P1V1 is not an exact replica of the preceding full-history Q treatment.

Sixteen paired source blocks × four arms =64 endpoints. Master981370001, sample seeds981370101–116.
Sort source IDs by hash of master+ID, rotate four-arm order cyclically (four blocks/order). One seed
per block, identical across arms. Same low66c root and c32 child, temperature0.5/top_p1,2048 native
tokens/call,8192 context, four workers,180s per endpoint. No decoding grammar or answer repair.
Initial actual native prompt plus allowance must fit without truncation.

## Runtime and decision
Use the already successful restart task/collector/owner with narrow explicit new namespace and
64-slot/3000s envelope adaptations, not a new service stack. Outer3000s from entry,work2700s,
owned2880s,cleanup180s,outermargin120s. Startup≤300 and collection≤2400 share work2700.
Checkpoint all planned slots before service start, all returned native calls and completed endpoints,
and final missing-slot inventory. Owner success is not all-endpoint availability.

If observations improve faithful use without extra child calls, test concise direct evidence on
new contexts next. If quoted actions independently help, test a compact procedural demonstration
against a same-length nonprocedural control. If neither factor isolates the earlier gain, consider
source-format/history-message structure rather than asserting a learned mechanism. A reproducible
effect still needs new context clusters and then whole free-root evaluation before publication.
