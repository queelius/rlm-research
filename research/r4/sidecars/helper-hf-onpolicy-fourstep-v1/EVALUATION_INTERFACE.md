# Step-aware native evaluation interface

This training owner never evaluates or selects a checkpoint. Its primary is fixed step4. Existing one-step evaluator seals are untouched and must not be pointed at these checkpoints: their step1 contract is intentionally incompatible.

Paths below are relative to this sidecar's `outputs/attempt-001`.

1. Require final `RESULT.json.status == "COMPLETED_FOUR_UPDATES"`, `completed_optimizer_steps == 4`, `primary_checkpoint_available == true`, `primary_checkpoint_step == 4` and exact `primary_checkpoint == checkpoint-0004`. A stopped run is not a successful primary experiment.
2. Verify the sidecar READY source/input/environment closure and pin its identity. Follow the four ordered `RESULT.json.checkpoints` entries, checking each state and `STEP_COMMIT.json` hash. Each commit is `UPDATED`, with honest cumulative step1/2/3/4 and the same READY identity. Verify every `files_sha256` member.
3. At step1, parent identity must be original c32 SHA `c32de1293c01bba5104eb1f123867649c71dd38e5194661ace4b17dcbbe66ba3`, and parent commit must be null. At stepN>1, parent identity must be the preceding checkpoint state SHA; parent commit path/SHA must point exactly to the preceding step's commit. Check optimizer state steps equalN, not1; carried first/second moments are intentional.
4. For each step, state pins `updates/update-000N/QUALIFICATION.json` and `COLLECTION.json`. Require32groups/128fresh actions, `optimizer_steps_at_collection == N-1`, all32 qualifications passed/finite/computed-before-step, current/old selected rows aligned, token error≤1e-5 and sequence error≤1e-4. First-four groups must have full-support audited with error≤1e-5. Recompute selected errors from recorded arrays; do not trust a boolean alone. Loss denominator remains128 and sequence reduction sum. Cross-check each per-group `REPLAY.json` against the qualification entry.
5. Collection authenticates `START.json`, `START_RNG.pt` and every group commit. Each group commit pins its `ROLLOUT.json`, `MASKS.npz` and `AFTER_GROUP_RNG.pt` and names the same frozen parent. Source IDs must exactly be the32 frozen training IDs in the saved permutation. This is fresh collection at each step, not reuse from c32 or a prior step. Saved RNG has complete current sampler/global state; no automatic resume semantics are implied.
6. Check checkpoint adapter/config/optimizer/RNG file hashes against state and commit. LoRA parameter names only, finite positive per-step delta, finite gradient norm, LR1e-5/weight-decay0/clip1, root/environment loss tokens0, and original c32 source identity must hold. A reviewer can load optimizer moments CPU-only to confirm the step counters; no GPU model load is needed for qualification.
7. Use only `checkpoint-0004/EVAL_BINDING.json`. Its child alias is unchanged; child path/adapter/config hashes must match that checkpoint. `child_only_update` pins state, optimizer and RNG, names this experiment, step4/cumulative4, original source child and `root_unchanged:true`. Build the expected binding by replacing only the child and adding this update metadata to the frozen original source binding; require exact remaining equality.

An independently prepared native owner should save its own dynamic ELIGIBILITY receipt pinning all four committed steps, final RESULT and the binding before service startup. Use fixed source requests/ordered schemas/temperature/seeds. No relabeling step4 as step1 and no automatic best-checkpoint selection. An optional predeclared1/2/4 curve must explicitly allow the requested step and independently authenticate its complete prefix; it is descriptive, not a primary-result substitute.

The training-only loader consumes no protected128, TREC-test or AGNews inventory. Further evaluation on the already examined new panel is adaptive panel reuse; retain its source-exposure limitation and keep missing/invalid outcomes distinct from observed errors.
