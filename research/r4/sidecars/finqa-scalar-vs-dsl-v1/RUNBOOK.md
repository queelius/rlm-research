# FinQA scalar versus restricted JSON DSL: fixed16 paired32

Question: does a known program-execution interface help the same small model answer a second task family? This is a calibration of direct scalar answers versus model-written arithmetic with host execution, not a novel RLM, decomposition method, or recursive planner.

Freeze16 examples from official FinQA dev revision `0f16e2867befa6840783e58be38c9efb9229d742`: sort SHA256(revision + newline + example ID), then keep the first16 distinct page filenames. No gold quality, supported-op, or model outcome filter. Pre-existing annotation flags remain host-only. No held-test or training mutation.

Both arms receive exactly the same original question, pre_text, table and post_text. Only the terminal answer-interface instruction differs. No retrieved/model_input fields, support annotations, gold programs or answers enter either prompt. Same Qwen3-4B-Instruct-2507 base with no adapter; native Qwen3 renderer; T=.5, same seed202609290000+i per pair, max384 output tokens per call,8192 total context. All32 native prefixes are saved before generation. Four question workers; direct/DSL order alternates by context index. Each answer costs one model call;32 physical calls total, not token-cost matched.

Direct returns JSON with only `answer`: finite number, numeric string or yes/no. DSL returns only `program`, one to five typed `[op,arg1,arg2]` steps. All10 official operation names are supported; prior results use #i, table operations use an exact unique row label plus `none`. Unknown or duplicate row labels, forward/cyclic references, unknown operations, duplicate JSON keys, bool-as-number, division by zero, nonfinite/unbounded values and excessive steps are invalid. No retry, normalization fallback, hidden operand replacement or arbitrary Python execution.

The new interpreter uses explicit bounded host arithmetic. It does not import or execute FinQA repository programs, Python `eval`/`exec`, or Sympy on model outputs. It follows the inspected official evaluator's numeric conversion (commas removed, percent divided by100), table-cell `$`/parenthetical-suffix handling, and final floating-point round-to-five-decimals. Literal magnitudes/results are bounded by1e100 and exponent magnitude by100. It intentionally rejects ambiguous table row labels rather than the official dict's last-row overwrite. This is an explicitly adapted JSON DSL, not official symbolic program-equivalence accuracy. Trusted, hash-pinned B05V3 **owner infrastructure** is reused via its existing compilation seam; generated outputs never enter that seam.

Primary: equality with supplied `qa.exe_ans`,16 planned per arm, not corrected semantic truth. Direct numbers are never rescaled using gold. Percentage strings explicitly mean ratios in both interfaces; programs can explicitly multiply by100. Preserve mixed-scale/noisy-label limitations and all cases. Secondary: interpreter validity and whether literal operand values occur in original evidence or the declared constant list. Value presence is not source identity, correct relevance, or faithfulness. Invalid returned output is an observed model failure; transport unavailable remains unknown, with cost subtotals/unknown counts and only known pairs used for wins/losses.

Owner/science/external caps700/600/800 seconds. Reuse runtime-qualified B05V3 engine registration and lifecycle, including mandatory post-dispatch qualification and cleanup; no warmup/filler model call. MAIN alone reviews/adopts/launches under its existing exclusive lock. `CPU_READY.json` is not automatic GPU admission.

Run CPU verification with the pinned native Python: `owner.py verify`. MAIN's launch argv is frozen in CPU_READY. No GPU was used during preparation. Focused tests cover all10 operations, percent scale, invalid/ambiguous programs, original-value presence, and a real paired native HTTP request→token decode→safe score fixture with current owner aliases. Native call record `response_sha256` is the inherited canonical JSON digest; do not compare it to raw response bytes. Raw response files are retained separately.
