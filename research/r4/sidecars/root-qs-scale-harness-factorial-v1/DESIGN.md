# Root question-sensitive scale × harness diagnostic

Status: approved CPU preparation; MAIN alone may launch the one-A100 owner.

## Question and fixed design

Does the exact question-sensitive fixed6 root retain its learned task-sensitive computation as a
single nested record context grows from 16 to 64, 128, and 256 records, and does the already-qualified
cumulative-return plus bounded-visible-view package help? The harness contrast is explicitly a bundle,
not an isolated memory intervention: control is current-batch return (`B`) with the original 20,000-byte
view, treatment is cumulative return (`C`) with the qualified 4,096-byte head/tail view.

The 64 endpoints are four preselected clusters × four nested sizes × two roots (unchanged fixed24 and
exact QS fixed6) × two harness packages. Each cluster keeps one protected-style J1 same-user
conditional-weight question fixed across sizes. The fixed child is c32. All host truths, including zero,
are retained. Four cells at the same cluster/size share one fresh seed; there are no retries or rerolls.

## Source selection and exposure

The candidate universe is the full authenticated 5,065-group TREC source-train pool actually used by
the c32 optimizer. Named root-training groups and QS train/dev/protected groups are normalized to source
group IDs and excluded. Remaining IDs are ranked only by a fixed SHA-256 namespace and ID, then the
first 1,024 are split into four disjoint 256-record clusters. Sizes are exact prefixes. Selection does
not use gold labels, string length, or prior outcomes.

These records are child-training exposed and may have appeared in prior research catalogs or readouts.
The defensible novelty statement is only disjointness from the frozen named root-training inventory,
not globally new data. The TREC source files, split manifest, source code, revision evidence, and license
are pinned by `READY.json`.

## Outcomes and limitations

The frozen primary endpoint is `faithful_and_strict` on the planned denominator. Secondary endpoints
are strict correctness, native availability, acquisition, retention, full aggregation, host-oracle
child-label diagnostics, and token/time/tool costs. Report paired fixed6-minus-unchanged effects by size
and harness, the size-256 minus size-16 survival DID, the package effect for fixed6 (focused on sizes
128/256), and the exploratory three-way contrast. Authenticated empty finals count as observed incorrect;
NULL is reserved for unavailable or unauthenticated native results.

There are only four context clusters, so this is an exploratory mechanism diagnostic, not an
inferential population claim. Root services are necessarily serial; harness cells are interleaved
inside each root-specific plan. Service startup, collection, release, and harvest share a single
3,570-second ownership budget inside a 3,600-second outer cap.
