# CPU preparation handoff

The approved four-policy study is implemented entirely in this independent sidecar. Existing collectors, builders, service wrappers, training inputs and queued closures were not edited. No model/GPU call was made during preparation.

New source inventory: adaptive_study.py (fixed 152 request bodies and inherited native seams), adaptive_metrics.py (gold-free routing/stage order and four-policy cost/accuracy), owner.py (one service, per-call checkpoints, ESCALATION commit and terminal host scoring), seal.py (complete closure/environment/CPU receipt), test_adaptive.py (two focused fixtures). DESIGN.md is the approved unchanged specification; PLAN.md records the bounded implementation scope.

The two CPU fixtures passed before sealing, including live commit order, all-distinct vote tie, missing-map fanout, shared physical-versus-logical cost totals, all 152/512 component inventories, fixed seeds/T0/output cap, preserved neighbor slots, ordered schema, actual tokenizer/native response validation and context bounds. The final sealing invocation records the fresh command, exit status and stdout/stderr in CPU_TESTS.json. Two upstream SWIG deprecation warnings are expected; they are retained, not suppressed. Focused Ruff check and formatting passed.

READY.json is the authoritative source/environment manifest and launch interface after seal.py succeeds. Its closure includes all new sources, generated inventory, fresh panel's 18 source/data pins, and the inherited size/target/c32/service closure. verify validates every file hash plus the ordered-schema component inventory. MAIN must independently review before launch.

Run interface: native Python → owner.py run --outer-seconds 1100; MAIN supplies one GPU, inherited credential, shared flock and 1200-second external timeout. Output is outputs/attempt-001, which must not already exist. No retry/resume/continuation path is enabled.

Stage evidence: calls/*/REQUEST.json, REQUEST_WIRE.bin, RESPONSE_WIRE.bin, RESPONSE.json and CALL.json; PROGRESS.json after every call. ESCALATION.json commits the exact ordered disagreement IDs, agreeing labels, unavailable IDs and hashes of the 16 original/A calls before selected singles, B, or remaining singles. Final RESULT.json separates datasets/policies/physical experiment cost and requires complete coverage/usage plus runtime qualification for its exploratory screen. OWNER_TERMINAL.json and EngineCore/pre-exec/cleanup receipts retain failures and cap-induced missingness.

The fresh panel contains 64 records/dataset with verified local-optimization/old-panel exclusions; TREC has five observed gold classes and still uses the full six-label schema. This is a known-style ensemble comparison with live selective smaller requests, not a novel grouping/ensembling algorithm or general recursion claim. Shared observations support paired component comparisons, not independent cold-service latency estimates.
