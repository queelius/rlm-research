# Independent audit: warm-start reference24

The calibration gives **no evidence that either historical checkpoint is a better operator-capable
start than the served zero-effect reference**. Released reference scored 2/8, success8 3/8, and
interface4 2/8 planned (5/8 available). Every one of the seven correct endpoints had gold zero;
all three policies scored **0/4 nonzero**. None of 24 episodes called the fixed child, so none
demonstrated acquisition, live accumulation, or a genuine category-conditioned reduction.

All roots received the same eight blocks and paired seed per block: four QSR/research-exposed

served mathematically zero-effect adapter, not bitwise bare-base transport.

## What the policies actually did

Static inspection of retained executed traces found 84 IPython actions and 60 tool observations;
all 24 episodes attempted tools, 22 included code mentioning the public files, and zero included or
made a child-API call. The policies repeatedly treated absence of labels in `records.json` as a
reason to answer zero, searched for literal category words in question text, or struggled with
JSON/bash. Nine available finals were exactly `Answer: 0`; seven happened to match zero gold.
Observed wrong scalars include success8's 17 for a zero-weight target and 16 for a count whose gold
was 2. Three episodes attempted package installation (including `pip install jq` or `apt-get
install`); this is retained executed behavior, not auditor reexecution.

Thus file access and arithmetic occurred, but no output was conditioned on acquired c32 labels.
The zero-only scores are compatible with shortcut/default behavior, not evidence of the target
acquire→accumulate→reduce→stop mechanism. The [diagnostic inventory](../../../../ARTIFACTS.md#unpublished-files "Not published: ../../analyses/root-warmstart-reference-live-2026-09-10/DIAGNOSTICS.json")
is text-only and does not rerun sampled code.

## Decision

Do not choose success8 or interface4 because of these scores: neither has a nonzero win or any
acquisition evidence, and interface4 is less available. For a clean prospective 72×6 SFT package,
the **served released reference is the least assumption-laden common start**, with an unchanged
served-reference readout. This is a design choice, not evidence that 857 is intrinsically superior
or bitwise bare base. Before spending a long training budget, require a fixed forward-only gate on
nonterminal acquisition/reduction targets and preserve real wrong c32 outputs. If that gate shows
no likelihood headroom, run the smaller interface/reachability test instead. The readout should use
the proposed readout-04–11 groups, not this exposed reference00–03 panel.

This exploratory four-context result can deprioritize performance-selected historical starts; it
cannot establish broad incapacity, fresh-context transfer, or a causal checkpoint effect independent
of fixed phase order.
