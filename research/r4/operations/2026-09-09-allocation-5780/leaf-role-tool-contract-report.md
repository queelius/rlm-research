## V2 prelaunch measurement correction

MAIN's prelaunch read found two V1 collector defects before acceptance or launch. V1 could set a
score before validating returned prompt identity/usage, leaving a nominal success after a later
native mismatch. Its summarizer could also dereference `score=None` after an HTTP or pre-score
failure. The preserved V1 READY above is therefore **superseded by `READY_V2.json`**; its science,
data, requests, prompt IDs, model, output namespace and clocks remain immutable history.

V2 admits an outcome only after authenticating the unique assistant choice, exact model, exact
native prompt tokens, integer native completion tokens, prompt/completion/total usage, assistant
role, finish branch, and either decoded completion text or the parsed tool envelope against the
decoded native token envelope. An authenticated tool-directed completion remains an observed policy
failure worth zero and is never executed. Any HTTP, JSON, prompt, token, text, tool-envelope, usage,
model, choice, or finish inconsistency retains raw evidence but resets completion and score to
infrastructure NULL. V2 normalization supplies NULL scores for every missing/pre-score record, so
analysis and STATUS still finalize with planned bounds.

Six additive regressions pass. They cover valid-looking content with corrupted returned prompt IDs,
an empty choice list, HTTP 500 before raw JSON, an authenticated native tool call versus tampered
arguments, exact owner-to-V2-driver composition, and all 96 completed free-ID attempt-003 responses
as read-only tokenizer/envelope compatibility fixtures. All 96 authenticate across parsed-tool,
literal-wrapper and ordinary final-text branches, and V2 reproduces their frozen strict scores.
This is compatibility qualification, not new experimental evidence or prompt equivalence.

The fixed shared clock is 1,500 seconds collector / 1,680 work / 1,770 owned / 1,800 outer in both
