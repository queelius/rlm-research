The coordinator never signals the predecessor or a replacement PID. A still-live original identity past its deadline+120seconds stops the handoff. The parent reviews this operation and publishes ACCEPTANCE.json, setting approved=true and binding exact PLAN hash, job argv and current hashes for every listed source/input. `acceptance-template` only prints an unapproved template. The coordinator copies one accepted snapshot into its new operation output and verifies those accepted source hashes before each job. Planned commands are proposals until that acceptance exists; no speculative endpoint is bound.

Order is fixed: owned anchor service/collection, then indexed SFT. GPU compute PID output must be entirely empty before each job; unknown query output is an error, not interpreted as empty. Every operation/job records source and command identity, owner, stdout, exit code, timeout, completion-marker hashes and GPU PIDs after exit. Nonzero return is not repaired or retried. A marker's presence is reported, not interpreted as scientific success. Wait, acceptance wait, GPU-clear wait, per-job work and total elapsed clocks remain separate. Existing outputs cause refusal; this is one fixed two-job handoff, not a scheduler or resume framework.
