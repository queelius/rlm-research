## 1. Correct output format is not enough to preserve useful predictions

With unchanged helper weights, explicit output IDs raised 64-item accuracy from
38.2% to 93.6% for question classification and from 60.1% to 96.3% for sentiment.
Both arms already had IDs in their inputs, and every output was valid. Small
batches were already accurate. The striking observation is therefore not merely
that formatting repairs a broken response: how the answer is represented can
determine whether the model's local task ability remains useful at larger batches.

This is our strongest current experimental centerpiece. It comes from six/four
source-context groups with repeated seeds/permutations, not thousands of independent
examples. The instruction and output grammar changed with the representation,
and indexed outputs used about 3.2 times as many tokens. Neither an attention
mechanism nor equal-compute improvement has been isolated.

[Completed result and audit](../../analyses/anchor-indexed-followups-live-2026-09-09/ANCHOR_REPORT.md).
The [completed grammar and placeholder controls](../../analyses/grammar-training-padding-controls-2026-09-09/REPORT.md)
narrow one alternative explanation. With similar output-token counts and the same
enforced structure, meaningful tags beat constant tags by 262/512 question labels
and 153/512 sentiment labels. All four context groups per task favor meaningful
tags. They also provide a changing position counter, so input-identity matching
was not isolated by that control. Free tagged
outputs were all invalid: no semantic contrast is available there. Numbering
answers is already established prior work; that alone is not a novelty claim.

A newly completed training control makes this direction more focused: the earlier
mixed-size-trained helper already scores 373/384 on long indexed outputs, versus
374/384 after specialized ID-target training. This does not demonstrate a useful
extra training benefit. It suggests testing how existing capability is exposed
by the interface before spending more compute on the same training recipe.
[Completed three-weight comparison](../../analyses/anchor-indexed-followups-live-2026-09-09/REPORT.md).

The completed randomized-identity control sharpens the question, but also exposed
a control confound. Meaningful source tags scored95.6%/93.8% on question/sentiment
labels; a changing ordinal scored28.0%/49.3%. All96 outputs were valid and output
costs were similar. However, ordinalp0001 and sourceq0001 share a numeral. A
post-hoc alignment by that numeral agrees with gold83.9%/93.1%, with improvement
in every ordinal call. The model frequently classified a different source than
the instructed displayed item. This does not rescue its task accuracy; it means
the overlapping ordinal condition cannot be treated as neutral bookkeeping.
The [completed384-call prospective control](../../analyses/identity-factorial-live-2026-09-09/REPORT.md)
now removes numeric overlap and swaps prefixes. Disjoint meaningful IDs retain
47–53point question-type gains and roughly35point sentiment gains over counters.
All four context sums per task/prefix are positive and all384 calls valid.
Removing overlap improves counters, but explains only part of the gap. These are
still the same exposed contexts, so fresh-context/second-weight replication is
more informative than another large same-context mechanism grid.

That [new-task/two-weight comparison is now complete](../../analyses/agnews-identity-live-2026-09-09/REPORT.md).
On four AG News contexts, meaningful source tags beat ordinal tags by42.6–47.3
percentage points; every output is valid and every context favors matching IDs.
The effect appears with both original and historical helper-SFT weights. Training
is not necessary for it, and changing the ID letter prefix has little effect here.
This is an important extension beyond the original two tasks, while the causal
role of particular output cues and the whole-RLM benefit remain unresolved.
[Primary audit](../../analyses/identity-counter-live-2026-09-09/REPORT.md),
[explicitly post-hoc diagnosis](../../analyses/identity-counter-live-2026-09-09/POSTHOC_NUMERIC_ID_REPORT.md).
This identifier-interference observation may be a more focused research lead than
a generic claim that output numbering helps. Mechanistic binding and index-selection
limitations already have substantial prior work; our behavior alone is not an
internal causal-mechanism result.

Two additional controls now narrow this lead. The [field-order experiment](../../analyses/output-cue-order-live-2026-09-09/REPORT.md)
found that the large matching-ID benefit survives when the label is emitted
before its ID. Writing the current ID immediately before the current prediction
is therefore not necessary. That is not equivalence of field orders.

The [completed reminder-frequency experiment](../../analyses/leaf-sparse-anchor-main-review-2026-09-09/REPORT.md)
has a particularly clear visualization. At one reminder per four answers,
accuracy is highest at the tag-bearing slot and usually falls over the following
slots. All144 outputs were valid. Dense matching achieves488/512 question labels,
482/512 sentiment labels and411/512 news labels; sparse reminders lose substantial
accuracy in every matched context–seed comparison. They save output tokens, not
accuracy. The next controlled comparison asks whether moving the ID after the
label shifts the benefit toward the next item. This is a more discriminating
behavioral question, not a claim about attention or a new architecture.

## 2. Training the coordinator improves complete RLM answers with a fixed helper

Reward-based root training increased exact final answers from 5/24 to 16/24,
with 13 paired gains and two losses. The helper stayed fixed. This is encouraging
because it changes the component that coordinates the work, rather than merely
making local predictions more accurate.

It is one training run on six context groups. Their questions were used in helper
training, though these compositions were new to root training. The setup already
provided a suggested procedure and worked example, not a tool-call prefill. The
[corrected native-token check](../../analyses/root-first-action-screen-2026-09-09/PREFILL_CORRECTION.md)
shows both models sampled the opener in all24 cases. The posthoc syntax audit
found usable first requests increasing from 13/24 to 22/24. We cannot yet say that
training learned general adaptive decomposition or that syntax explains a causal
fraction of the gain. More calls were used, so it is not a uniform efficiency win.

[Completed root result](../../analyses/root-continuation-live-2026-09-09/REPORT.md) and
[first-request analysis](../../analyses/root-first-action-screen-2026-09-09/REPORT.md).
An independently seeded training replication and a syntax-controlled comparison
would strengthen or narrow the interpretation. The queued return-instruction
comparison tests a different, complementary interface question.

Update after that comparison completed: with ordinary instructions, original
versus trained scores were 6/24 and 20/24 on fresh sampled runs. The same
return-type reminder raised the original model to 9/24 but lowered the trained
model to 14/24. Its trained-model effect was negative in four contexts and tied
in two. Thus the trained-weight advantage appears again, and the instruction's
effect depends on which weights use it. This is prospective experimental evidence,
but the same six contexts and same trained checkpoint remain; do not call it an
independent training replication or proof of a JSON/list failure mechanism.
[Completed instruction-by-weights comparison](../../analyses/root-contract-factorial-live-2026-09-09/REPORT.md).
Keep ordinary instructions as the working trained-root condition while testing
the independent seed and later transfer; do not promote the reminder by default.

The independent-seed training repeat is now complete and audited:9/24 original
versus15/24 selected-step6,11 paired gains,5 regressions,8 ties. Four contexts
improve, one ties and one worsens. The frozen earliest-max rule chose step6 after
validation2,2,1,3,3 of8 at steps0,2,4,6,8. Step8 was saved but not evaluated. This
supports a positive direction under another training seed, not a precise effect
estimate or confirmation on new context groups. Its six-update infrastructure STOP
is preserved separately from the successful continuation.
[Completed independent-seed audit](../../analyses/root-independent-seed-continuation-live-2026-09-09/REPORT.md).
The [broader sixteen-update campaign](../../analyses/root-broad-equality-continuation-live-2026-09-09/REPORT.md)
is complete. Its fixed final model scored 16/48 versus 13/48, with eight gains
and five losses. Crucially, the new 64-record composition comparison stayed
at 5/24, reserved-category queries fell from 3/12 to 2/12, and both models
scored 0/4 on 256-record cases. The modest pooled improvement should not be
presented as general aggregation or decomposition learning.

This narrows the earlier positive result: reward training helped on the
earlier limited contexts, but the broader recipe did not show comparable
transfer. All sixteen updates and root-only credit were verified; this is
not an apparent failure caused by training never happening. The intermediate
validation maximum was not substituted for the prespecified final model.

Do not flatten this into “nothing changed.” A
[post-hoc count-distance screen](../../analyses/root-broad-posthoc-examples-2026-09-09/REPORT.md)
finds mean absolute error4.625→0.875 among24 pairs with numeric answers from both
models; nine pairs improve and two worsen. That is an outcome-selected subset,
not a new primary or full-population causal effect. It motivates prospective
near-miss and exact-answer measurements, alongside interface/coverage controls.
The next useful training target follows the completed interface-uptake and
question-sensitive planning experiments: reliable child contracts and native
root interface/output competence, before another adaptive-planning RL campaign.

## The possible paper connecting them

**When does a model's ability to solve small parts survive the process of combining
those parts into a larger answer?**

The two results are complementary, not yet one demonstrated causal chain. The
first changes helper-output representation; the second changes root weights.
We still need an end-to-end intervention showing that the improved representation
helps the coordinating system use the evidence and answer correctly. The new
identifier study makes the gap concrete: wrong item-label correspondence can still
preserve whole-category totals. A counting task can legitimately succeed despite
permuted labels. Tasks linking semantic labels to record metadata may expose where
source correspondence matters; do not assume item gains translate to count gains.
The [72-episode optional helper intervention](../../analyses/receipt-ablation-live-2026-09-09/REPORT.md)
is complete: unchanged21/24, raw0/24, receipt0/24. Neither new arm called the
helper, so the value of an actually consumed receipt is still untested. The new
prompts also removed a familiar procedure. This failure makes interface portability
a concrete next question: can matched API teaching restore uptake, and does the
trained coordinator depend more strongly on the old procedure? The
[completed uptake follow-up](../../analyses/receipt-uptake-live-2026-09-09/REPORT.md) restored
some use but not final accuracy. It exposed both invalid child replies and
incorrect root consumption of valid evidence. The
[completed planning pilot](../../analyses/adaptive-filter-live-2026-09-09/REPORT.md) likewise
found no free-root helper use and unreliable programmed all-file procedures.
The child-role wording pilot did not improve accuracy or reproduce the motivating
tool loops. These findings motivate the active typed-child comparison and a
separately declared interface/output SFT warm start; they do not establish that
either repair works. Requested-subset validity checks structure, never truth.

The [completed typed-helper audit](../../analyses/typed-helper-child-live-2026-09-09/REPORT.md)
now confirms that eligible child outputs can be made structurally reliable without
establishing whole-task accuracy. A [hand-written filtering baseline](../../analyses/typed-adaptive-operator-live-2026-09-09/PRIMARY_REVIEW.md)
then achieved the expected useful behavior: six jointly correct cases needed
48 helper calls with all-file processing versus6 after filtering. This is a
reference behavior for learned planning, not a novel filtering algorithm.

The [interface-SFT run](../../analyses/root-interface-sft-live-2026-09-09/REPORT.md) teaches real
helper use in24/24 cases versus0/24 before, but only changes strict accuracy
from1/24 to2/24 and worsens final formatting. Most first actions copy a short
example, and final-answer examples received only5.2% of target-token weight.
This is valuable prerequisite evidence, not an additional training-success claim.
Terminal-reward training from that exact checkpoint is now active; a separate
equal-row weighting control preserves the same demonstrations. These tests
distinguish interface uptake, task coverage and correct reporting instead of
treating “used a helper” as success.

A focused empirical paper could document the failure points, compare targeted
interface changes, and test how training interacts with those changes. A broad
claim to a new RLM architecture or general compositional learning would be premature.
The [nearest-prior-work review](../../analyses/publication-positioning-2026-09-09/REVIEW.md)
explains why IDs, RLM reward training, typed wrappers and generic co-adaptation
cannot be presented as firsts.

The [official-runtime comparison](../../ideas/2026-09-09-official-runtime-comparison.md)
identifies three useful next modifications: source-bound returns, visible coverage
feedback, and a control separating code use from JSON syntax. They are proposed
experiments, not established novel methods or completed gains.
