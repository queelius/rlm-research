## Question

Can a learned choice of intermediate report preserve enough information for correct cross-partition
composition on held-out query and structure combinations?

## Why it matters

Typed or parseable outputs are not necessarily sufficient for the parent computation. A learned
interface that preserves task-relevant information across partitions could be a substantive RLM
contribution, but only if it beats ordinary reports and exact nonrecursive alternatives rather than
a deliberately lossy straw baseline.

## Evidence so far

There is no experiment and no result for `claim:sufficient-information`; it remains a proposed
hypothesis. The relevant prior evidence is indirect. `claim:correspondence-boundary` supports local
source-linked alignment, while `claim:bridge-no-task-gain` shows that improved label agreement need
not improve whole-task answers. `claim:reduction-not-restatement` identifies missing or wrong
combination as a plausible downstream boundary. `claim:plan-negative` shows that first-action
strategy teaching did not supply the missing transferable procedure. Exact experiment/report links
are recorded in the metadata above and summarized in the sealed [claim
cards](../analyses/research-factory-2026-09-09/CLAIM_CARDS.md).

### Later sealed update outside the catalog cutoff

The [three-root bridge audit](../operations/2026-09-09-allocation-5780/audit-report.md) adds stronger
contrary evidence: checksum remains at floor across roots, map count effects are not robust across
roots, and focused cases show container misuse or failure to combine a complete visible map. This
does not test learned report choice, but it sharpens the need to distinguish information content
from the consumer's ability to use it.

### Partition-pilot result after the catalog cutoff

The sealed [partition audit](../analyses/root-partition-report-live-2026-09-09/REPORT.md)
(report SHA256 `6d72da758a4d69561445b1799a7d78662550c948c92da5f687745f9016c7206a`;
final-manifest SHA256 `3adb397aba7a6b095fdda62865fffbcb44661366c000e1368cc546c09e1ef3db`)
scores all five endpoint arms 0/8 strict, but this is an instrument-limited result, not evidence of
communication loss. There are four engineered worlds and four partition pairs, not eight
independent worlds. All 24 extraction calls stop naturally and return the exact 16 original triples
(384/384 emitted triples correct). Reconstructed full evidence implies gold on 8/8 coordinates.
Yet all eight full-report parents hit the 256-token cap before an answer, while expanded direct
outputs retain prose instead of strict JSON and are semantically complete in only two of four unique
worlds. Ordinary child prose also preserves positive facts sufficient for all four cross-partition
answers under a separately labeled manual reduction. The root did not successfully compose those
facts, but the channel did not demonstrably lose them.

### Separating answer format, usable records and information loss

The [final-format comparison](../operations/2026-09-09-allocation-5780/partition-final-interface-audit-report.md)
returned all24 endpoints. Constraining the answer format made12/12 outputs valid,
but none correct; all12 unconstrained outputs also failed the strict answer
contract. A well-formed answer alone did not solve the combination problem.

The [native Python follow-up](../operations/2026-09-09-allocation-5780/native-partition-join-audit-report.md)
then solved2/8 direct-input tasks with Python and0/8 without it, with all16 native
finals available. All eight tool-using roots copied the real inline facts into
programs; six failed while parsing the sentence format. They neither opened the
evidence file nor called children. This supports a narrow record-access diagnosis,
not yet reliable cross-partition composition.

The same run's report comparison never reached the root: only5/24 child reports
reproduced every source record, so all32 report-root slots remained explicitly
unrun. Importantly, the19 incomplete reports were strict subsets with no invented
triples. Four of eight report packages retained all query-relevant triples, and
six still contained enough information for an exact host join. The
[additive erratum](../operations/2026-09-09-allocation-5780/native-partition-join-audit-report-erratum.md)
corrects the relevant-triple completeness count to4/8. An extraction-contract
failure is therefore not automatically loss of the answer. No gated outputs are
repaired, rescored or counted as observed root failures.

## What remains unknown

It remains unknown whether a model can compose ordinary or structured reports after final-format
and output-cap failures are removed. Report verbosity, prefill, cap, child termination and content
all vary together in the pilot. Full incidence beating a deliberately lossy local-winner report is
true by construction and cannot establish a learned contract. Partition robustness is also
distinct from depth generalization.

## Smallest discriminating next experiment

The format-only and native-Python comparisons above have now been completed.
The next accepted24-root mechanism probe keeps every original fact and the optional
tools, but compares sentence records, an offered JSON record file, and immediately
visible JSON records. It tests whether accurate machine-readable access removes
the observed lexical parser failures. These are four exposed worlds with two
paired seeds each, not a fresh generalization panel. See the
[frozen design](../ideas/2026-09-09-native-join-record-interface-design.md) and
[live queue](../RESEARCH_QUEUE.md). Only after establishing usable inputs should
ordinary versus fuller reports be compared on fresh worlds, with explicit costs
and matched facts, final contract and computational resources.

## What would justify a stronger claim

First justify interface feasibility if sufficient reports beat ordinary reports on cross-boundary
correctness at measured cost and exact code does not explain the effect. A learned claim additionally
requires held-out learned representation or report selection across query and structure combinations.
Revise if length or exact code explains the gain, and retire a recursion claim if a nonrecursive
baseline matches it.
