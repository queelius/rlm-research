# Proposed next comparison: inspect literal request strings

Recommendation, not implementation or launch. The observed selector failure is concrete: both source documents contain “write a email about …,” while the root invents “write an email,” “message,” “short email” or “story.” All8 failures use an otherwise teacher-shaped role/ordinal/successor program. Extra retries alter bookkeeping instead of inspecting the input. A task-neutral inspection instruction can therefore test a real missing behavior.

One proposed universal addition: **“Before exact matching, inspect the actual user-request strings in the supplied document. Use the observed spelling and grammar rather than reconstructing request wording from the final question.”** No email-specific hint, example, source index, gold, generated catalog or supplied answer. The root must choose and perform the inspection itself through the unchanged environment; the harness does not precompute a request index.

Retain all8 fresh contexts × the same4 seeds, fixed cp32, source bytes, T0.5, max2048/action, six total root+child turns, current observation limits and terminal-strip-disabled. Reuse all32 current trajectories only after exact model/environment/source/seed binding checks. The sole intervention is the appended generic instruction; prompt tokens intentionally change.32 new trajectories, variable physical calls under the same caps—not matched actual token/call cost, since useful inspection may take another tool turn. MAIN alone decides admission.

Primary remains raw exact plus unavailable accounting for all8 G4 vectors. Mechanism diagnostics separately record whether the root (1) actually prints/inspects literal user-request strings before selecting, (2) uses a source-observed string rather than guessing, (3) retrieves clean target stdout, and (4) transports that result as an exact final. Preserve all32, including the24 already-clean retrieval controls; do not filter to emails or replace scores with normalized matches. No execution of generated programs during analysis.

If actual inspection restores the email targets but raw exact remains limited by copying, conclude a retrieval-policy improvement with an unsolved terminal-return bottleneck. If the first program stays unchanged or merely substitutes another guessed string, the instruction did not induce the proposed mechanism. Correctness gains without observed inspection do not establish that mechanism either. Uniform-zero failed groups currently cannot teach this selector correction through G4 binary contrast alone.

This is an adaptively motivated harness/policy-interrogation experiment on an exposed8-case panel with shared MRCR task/fewshot framing, not a new recursive algorithm, learned routing result, or independent-source generalization claim.
