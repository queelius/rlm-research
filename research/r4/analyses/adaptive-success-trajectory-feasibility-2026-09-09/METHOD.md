## Conservative candidate gate (not a reward rule)

A confirmed candidate must satisfy all of these:

1. Exact planned training coordinate, strict success, completed/episode.ok/trace.ok, no runtime/provider/native integrity errors.
2. Full query-relevant source-ID coverage from actual source-bound valid child returns, with no unresolved conflicting target-membership predictions for repeated relevant IDs. Global queries require all records; single-user queries require the public user subset. Extra inspected records are allowed.
3. Every relevant record's target-vs-nontarget membership matches host labels: target false positives and false negatives both0. Wrong nontarget class names alone do not invalidate the asked target-count task. Report them separately as a stronger reusable-map diagnostic.
4. The returned evidence implies the actual gold count, and recorded root code/observations show a faithful query-specific reduction and final submission. Mere equality between a complete-map count and the final answer is only a provisional arithmetic-compatible success. A printed integer matching final/gold alone is not proof of how it was computed.

Aggregation is pass/fail/unobservable. Inspect successful complete-map traces statically and use only recorded code, native messages and observations; do not execute generated Python. An explicit source-bound reduction whose inputs/scope and result are auditable can pass. Partial coverage, guesses, direct root classification and unstructured claims are separate strategy categories, not automatically bad policies. This deliberately conservative child-evidence screen is not a universal requirement that all correct strategies recurse or emit full maps.
