# Interface72 independent audit method

Frozen after MAIN announced the launch at approximately 08:14 UTC on 2026-09-10,
but before this auditor read any endpoint, aggregate score, native completion, or
cost outcome from the new attempt. This is therefore post-launch, pre-outcome-read
method documentation—not a claim of prelaunch preregistration. The auditor did not
author the task-spec study or its implementation. Prior work included the separate
warm-RL candidate and audits of ancestor operator studies.

## Fixed scope and primary accounting

Audit READY SHA256 `b90d595b0fe43ecd29d5e27160fe1ebc82ad0cb235374dae669dfc50bb809d0b`
and exactly 72 planned endpoints: 24 paired task blocks across eight exposed
composition contexts, each sampled once under unchanged U, redundant prose P, and
redundant JSON J. The same task/seed is paired across arms; cyclic dispatch order
is retained. The 24 tasks are the three composed families only. This is an
exploratory interface comparison, not a primitive estimate, fresh-context
replication, or proof of general task-spec following.

Primary outcome is strict authenticated dataset correctness on the planned 24
per arm. A completed genuine native final that is wrong or malformed is zero.
Missing RESULT, provider/infrastructure exception, unauthenticated response, or an
unfinished tool branch without a genuine native final is NULL. Never repair,
execute, reorder, infer, or salvage an answer. Report successes/24, available-only
diagnostics, and conservative bounds `successes/24` to `(successes+NULL)/24`.

Report all 24 matched J−P, P−U, and J−U blocks with wins/losses/ties among jointly
available endpoints and the exact one-/two-/three-arm NULL pattern. Also report
paired per-context planned means (three tasks per arm) and contrasts over all eight
clusters. Do not treat 72 endpoints as independent. Preserve four zero-gold and
20 nonzero blocks separately. A paired seed controls sampling within a task, not
serialization length, FLOPs, dispatch order, or shared-context dependence.

## Native and source authentication

Independently match each coordinate to the frozen plan, policy, model alias,
system/user prefix, seed, sampling parameters, tool inventory and exact first
prompt IDs. Require a unique choice, valid model/endpoint identity, coherent usage,
finish branch, native completion token IDs/text or authenticated tool envelope,
and no outstanding tool call for a native final. Preserve wrong-route and malformed
completed outputs as observed zeros; transport/native inconsistencies are NULL.

Verify that U keeps the historical four input files and prefix exactly, and that
P/J add only the frozen `task.txt`/`task.json` plus advertised sentence. Confirm
records, query, batch helper and public metadata bytes against frozen inputs.
Private gold and `ANTI_COINCIDENCE.json` are audit-only and must never appear in
model-visible files, prompts, child calls, or runtime overlays.

## Mechanism review

Score and faithfulness are separate. Manually inspect every available success and
every endpoint with a genuine metadata read or child acquisition; inspect enough
contrasting failures to characterize each route. Link judgments to exact node,
program, observation, native and physical-file hashes. Do not execute sampled code.

Classify, separately:

1. metadata advertised, actual file retrieval, successful parse, and which frozen
   fields enter subsequent executed logic;
2. genuine child request and authenticated returned ID→label map;
3. actual state retained by the root (complete, sufficient, partial, overwritten,
   literal, fabricated, or unknown), without convenient union/reordering;
4. executed requested operator, A/B categories, all-record/all-user scope, strict
   threshold where applicable, observed scalar, stopping, and native final;
5. dataset correctness, observed-map correctness, and task-faithful correctness;
6. zero/best-constant compatibility and equality to each pre-frozen simple
   alternative in `ANTI_COINCIDENCE.json`.

A file-name mention, `open` string, parsed object, correct scalar, or output alone
does not establish metadata use. “Use” requires an observed read/parse and concrete
dataflow from relevant parameter values into executed selection/reduction. A
faithful computation may still be dataset-wrong because of genuine child errors;
retain that as a distinct positive mechanism diagnostic, never a repaired score.
Wrong-operator coincidences remain primary strict successes but not faithful ones.

## Cost and interpretation

Union every raw physical record on disk independently of RESULT and owner summary.
Report prepared slots, proven attempts, HTTP responses, choice-bearing/native
completions, root/child calls, returned finals, per-arm/per-block calls and known
input/output/cached tokens; count unknown usage explicitly. Local physical cost is
not provider billing. Retain partial/torn artifacts and distinguish attempted
failure from unstarted work.

J−P is the closest representation contrast but bundles serialization, extension,
discoverability, token count, and any arm-order effects. P−U tests redundant
explicit wording/file affordance; J−U tests the whole interface package. Evidence
for useful JSON-specific uptake requires J to improve faithful nonzero composed
execution across multiple contexts over both P and U, with actual metadata use and
no availability collapse. P≈J>U favors explicit redundant task access, not JSON.
Score gains caused by coincidences or final formatting do not establish operator
competence. Null bounds, small clusters, fixed policy, exposed sources and a single
paired seed constrain every conclusion.
