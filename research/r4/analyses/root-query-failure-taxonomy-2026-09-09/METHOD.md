# Posthoc query-transfer failure taxonomy

This is a bounded posthoc review, not a new endpoint or outcome-blind hypothesis. The two sealed reports have been read: high-LR versus low succeeds 2/8 on query transfer in either arm; bounded RL before/after succeeds 0/8. Review all eight query coordinates in all four arms, including successes as controls (32 trajectories), without selecting examples as representative. Do not read the active authored plan-SFT outputs.

Authenticate the existing reports/manifests and query raw artifacts once. Use actual WireTrace branches ending at the final root call, verify the flattened physical prefix against the captured native root request/completion, and inspect recorded root code/tool observations only. Never execute sampled code. Child outputs are available to the REPL; only delivered tool observations on that physical root branch establish what was displayed to the root model. Child maps alone do not prove root consumption.

Separate: (1) unavailable/runtime or strict-format outcomes; (2) incomplete or wrong query scope; (3) query-relevant label mistakes, noting target false-positive/negative cancellation; (4) demonstrably wrong program reduction of recorded labels; (5) correct scalar visibly computed but wrong final restatement; (6) correct host-implied count from supported visible maps without a verified computed scalar; (7) unobservable/ambiguous. Categories may overlap; report explicit denominators and no unsupported mutual-exclusivity/prevalence claims. A program that faithfully prints a wrong quantity is not a final-copying failure. Recognizing a literal map or scalar is not a general Python interpreter.

Store trace/node/request pointers and hashes plus bounded per-case evidence, then a concise all-coordinate taxonomy and one or two ranked prospective followups. Proposals must isolate the identified deficiency, preserve model/child/task controls where possible, state exposed-source transfer limits and actual training/compute changes. A renamed training seed on deterministic full-batch/dropout-zero optimization is not meaningful replication by itself. No implementation, GPU, model/network/service actions, source changes or queue edits are authorized.
