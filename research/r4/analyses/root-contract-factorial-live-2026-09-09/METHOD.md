# Root return-contract factorial: frozen analysis method

Frozen before any new root96 outcome inspection on 2026-09-09. At preparation the accepted
coordinator was waiting for its exact predecessor and the root96 output directory did not exist.
The analyst has previously seen the transfer readout and motivating posthoc examples; this is
not a scientifically unopened task set or a confirmatory analysis.

## Question and units

Does the literal JSON-text return-type reminder improve exact task success within each frozen
root, and does the trained-root advantage remain under that reminder? This is a prospective
instruction intervention, not a repair of a demonstrated failure in these new trajectories.

The immutable plan has 24 matched task/seed coordinates, nested in twelve tasks and six exposed
64-record context groups. Each coordinate has original/step8 root × unchanged/contract prompt:
96 planned episodes, 24 per cell. Both weights use the same frozen c32de child. Root weights run
in two sequential service phases; instruction arms are balanced within paired dispatches.
Weight is confounded with phase/time/order. Common seeds do not guarantee identical trajectories.
Do not analyze 96 episodes as independent or claim fresh-task/pretraining novelty.

## Primary outcome and contrasts

Recompute the existing strict terminal outcome from each saved episode using the frozen scorer
projection and compare it to the saved derived value. Keep its binary result only where the
original projection has a completed, scored, observable terminal. Malformed/wrong completed
policy outputs retain their original zero. Operational failures, unobservable terminals and
unrun coordinates remain null, not policy negatives and not repaired successes. Preserve every
recorded coordinate, its failure category and all planned denominators.

For each of the 24 matched coordinates let Y(weight, prompt) be this outcome. Report:

- Prompt improvement in each root: Y(weight, contract) − Y(weight, unchanged).
- Weight advantage under each prompt: Y(step8, prompt) − Y(original, prompt).
- Interaction: prompt improvement(step8) − prompt improvement(original).

Compute a contrast only when all outcomes needed by that contrast are observed. Report planned
and observed matches, sums, mean percentage-point differences, favorable/unfavorable discordant
pairs and ties; the interaction can be −2 through +2 and is not itself a binary success rate.
Show all four cell successes/observed/planned and six context-group summaries (four matched
coordinates per context). If missingness differs, also show complete-four-cell matched
contrasts and descriptive missing-outcome bounds; do not replace nulls in the primary analysis.
No p-values, independence-based standard errors, or outcome-selected subgroup promotion.

## Secondary observations and costs

Use saved trace/message/code/observation data only. Never execute generated code. Preserve
first-root structured-tool presence, finish reason, completion/action length and missingness.
Root branch code is parsed with Python AST for narrow `json.loads` and `.extend(x.answer)`
markers; marker-positive means syntax is present, not that it executed or caused the outcome.
When any inspected code cell does not parse, aggregate absence is unknown rather than zero.
Report parsed/unparsed/no-code denominators. Tool TypeError/JSONDecodeError markers describe
visible observations, not a complete taxonomy or proof of transport failure.

Authenticate trusted root/child identities, renderer, sampling, seed and exact physical causal
tokens using the existing root exporter. Exporter failure is a separate integrity diagnostic;
do not silently change the task score or erase failed/incomplete episodes. No full semantic
code audit, response repair or extra-model query is in scope.

Count all retained request-local native attempts, including those not committed into complete
episode traces. Report exact physical input IDs/action IDs where present, logical usage and
wall time separately. Recover cache counts only from explicitly recorded wire usage fields;
preserve absent counts as null and show known-count sums plus missing-call denominators.
Do not add cached tokens to logical prompt counts twice. The frozen driver projects physical
cached tokens as null even when wire usage exists; this additive audit may recover those raw
values without editing it. Do not equate summed concurrent call latency with elapsed GPU time.
Record startup/collection/release/operation timing and inherited retry waits as actual costs,
not invented inference totals. Request-only or incomplete bodies get explicit unknown costs.

2. Monitor only process identity, operation events, terminal-marker existence and saved-file

3. After operation result/STOP and collection termination, read the completed raw outcome set

4. Write REPORT.md, METRICS.json and SOURCES.json only beneath this analysis directory. Hash

   Preserve terminal stops, failures and incomplete denominators. Rehash consumed evidence at
