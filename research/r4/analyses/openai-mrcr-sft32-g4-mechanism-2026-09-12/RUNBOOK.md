# Fixed checkpoint32 G4 mechanism readout

This is a one-shot CPU readout of the V4 attempt only: eight original training contexts, four fresh trajectories each. It is not a heldout evaluation or an optimizer. The original binary exact-string outcome is recomputed separately from the inherited continuous official MRCR score. Unknown episodes are neither wrong nor zero-reward samples; incomplete groups receive no RLOO advantages.

The analyzer reuses the reviewed original native-to-trace classifier and official scorer, independently redecodes the saved native token arrays through the qualified terminal hooks, and compares primary availability, exactness, score, mapping and initial-prefix checks against saved results. This is source-to-raw verification, not independently implemented training or likelihood qualification. The unchanged V1 scientific core is imported read-only; only V4 is authoritative for actual execution. The existing checkpoint qualification is trusted, while the exact live binding is checked against the fixed cp32 binding.

Per-group output includes binary variance, complete-group RLOO advantages, unique answer hashes, first-program/native-path agreement, clean target stdout, teacher AST identity and failure categories. Per-turn chosen logprob/surprisal is descriptive native evidence, not full-distribution entropy or a verified HF behavior likelihood. Four-sample answer entropy is only empirical answer diversity. The last root action may be another tool call: final-only credit is eligible only for an actual committed non-tool text final. No generated code is executed by this analyzer; AST parsing and saved observations are inspected only.

The proposed next decision is conditional, not admission: at least two complete mixed groups with identical first native paths and clean target stdout suggest an all-root versus actual-final-only credit comparison; other mixed groups suggest all-root credit; collapsed rewards suggest reviewing exploration or predeclared harder training inputs. An incomplete or unqualified owner cannot promote a global G4 finding. All-correct groups have zero binary RL contrast. No heldout selection, resampling-until-success, model queries, or optimizer changes are authorized.

CPU evidence: two focused fixtures (mixed/unknown G4 math and an actual archived native tool-to-final transcript) plus a separate actual `collect_v4.run` proof through five unmocked verification layers to a CPU-only checkpoint-binding sentinel. This catches the nested entry bug rather than merely calling an outer verifier. No science output or GPU call was created by that proof.

Run with `CUDA_VISIBLE_DEVICES='' PYTHONDONTWRITEBYTECODE=1 /project/alex_phd/envs/prime-rl-5990b1b/bin/python analyze.py check --output REPORT-001.json` from this directory. It checks once, returning PENDING if the accepted attempt has no owner terminal. No polling is installed. Use a fresh report filename after completion. Preserve prior failed V1/V2/V3 artifacts and do not infer results from them.
