## Decision and audit closure

The strongest next diagnostic is a contemporaneous matched comparison of the current optional-tool transport versus a syntax-only valid tool-envelope constraint, with the same fixed full panel, raw maps, root, native role, caps and new paired seeds. Leave code strings, label semantics, tool choice and root final unconstrained; no algorithm, answer grammar, helper, parser repair or source repair. Its narrow question is whether valid action serialization restores executed reductions, especially the six weight no-finals. It would not by itself solve the18 malformed finals or source errors. First establish CPU feasibility of such a native envelope constraint; this audit does not authorize implementation or a public API change.

Do not reward file opens or extend narrow map-copy SFT merely from this result. If a warm-start is considered, actual failure evidence supports diverse native state-loading→valid execution→short final trajectories, with acquired-map errors explicitly separated from operator targets and evaluation labels never leaked. Source fidelity is a separate bottleneck: improved root reduction cannot repair nine faithfully wrong outcomes by itself.
