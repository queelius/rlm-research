# Independent receipt-uptake96 audit method

Frozen before the uptake output directory exists, and before any new outcome is
read. This is a terminal-only CPU audit, not launch authority, a scoring change,
or a training decision. The parent will trigger it after the accepted operation
finishes or materially fails. No polling loop, generated-code execution, GPU
access, process signaling, lifecycle lock, or modification of run artifacts.

## Question, units and fixed inputs

Primary: does restoring the exact familiar procedure paragraph increase
native-corroborated helper uptake under identical explicit API teaching? Report
R minus D separately for original root and historical step8 root. The interaction
is the difference of those two within-root contrasts. U is the familiar-package
reference. V minus R is receipt availability **plus** its minimal access and
extraction documentation, not a pure parser intervention. D is not receipt72's
old replacement prompt; this experiment cannot retrospectively isolate the cause
of that failure.

The frozen grid is 96 coordinates: six already exposed 64-record contexts, two
count questions per context, one task-specific seed, two prescribed roots and
four arms. There are 12 paired task/seed units per root, nested in six context
groups, not 96 independent trials. The source questions are leaf-training
supported and repeatedly root-evaluated development data. No new-context,
base-pretraining cleanliness, or broad generalization claim.

Arm names are unchanged (U), taught_raw (D), restored_raw (R), and
restored_receipt (V). D and R differ only by inserting the original procedure
paragraph. R and V differ by the interface-availability sentence and the short
receipt access/extraction block. U preserves prior prompt bytes. Context, source
IDs/order, question, gold-only host scorer, public catalog, sampling and weights
otherwise follow the accepted specification. All offered code is only a prompt
example; calls remain voluntary. No reward shape, forced coverage, fallback,
semantic validation, answer repair or replacement episode is introduced.

## Authenticate once, then project terminal artifacts once

INPUTS_AUTH.json records the accepted operation, READY/spec closure, prior sealed
receipt72 audit references and prospective coordinate checks. Hash each unique
frozen path once into a cached map. At terminal, compare seals to that map and
authenticate only new operation/phase/service/capture artifacts once. Do not
rehash model/source closures per episode or invoke the frozen expensive verifier
inside a loop. Hash and project each new raw episode, routing request/result,
wire response and native trace once; reuse indexed request IDs and a single
tokenizer. Never execute generated code. Reusing a pure parser or AST inspection
does not execute model code.

Require the actual operation RESULT/child EXIT, run TERMINAL (or STOP/error),
phase STATUS and service-release records. Keep parent, child, scientific terminal
and release statuses distinct, including nonzero exit without inference failure.
Check every planned coordinate against the frozen row, task hash, public prompt,
context bytes/hash, source group/catalog, seed, phase, aliases and bindings.
Request IDs come from actual JSON fields, not filenames. Audit trusted depth and
native causal linkage, full physical prompt token IDs and actual native sampling;
separate verified sampled turns from all physical requests and request-only tails.
Check physical aliases against the authenticated phase's original/step8 plus
fixed-child binding and serving evidence. Do not equate helper prompt substring
matching with equality of a whole rendered physical prompt.

If immutable identity is materially inconsistent, stop the affected scientific
projection, retain evidence and notify the parent. Do not manufacture a match or
silently exclude inconvenient outcomes. Missing capture is a measured limitation.

## Uptake evidence ladder and conservative attribution

Retain each raw helper-log line, event position, byte hash, claimed call/session
ID and any duplicate/conflicting claim. The log and helper files are root-writable:
a matching hash proves retained bytes, not independent authorship or semantic
truth. Do not collapse events by call_id and overwrite duplicates. If a result
cannot be uniquely linked to a consistent request, keep that linkage unknown.

1. Source inspection: root code contains a source_records call; separately record
   whether that cell ran and a public-catalog observation was returned. Text in
   the initial example is not policy action. A code marker alone is intent.
2. Helper intent: an executed/intended rlm_records call, including validation
   failure before dispatch. Distinguish parsed AST, unparsed tool arguments/code,
   cell execution/error, literal helper event and ordinary rlm use. Missing AST
   information is not zero calls. Alias/dynamic invocation can be unobservable.
3. Primary uptake: at least one source-valid helper-request claim whose exact
   reconstructed request text is embedded in an authenticated native child
   prompt. Reconstruct source IDs, selected record bytes, query and vocabulary
   from frozen public catalog plus the claim; verify all recorded source fields.
   The endpoint is matching claim plus native request evidence, not an
   authenticated causal assertion that an unmodified helper authored the call.
4. Returned map: independently parse a raw child answer using the frozen strict
   ID-to-label-object parser, with requested IDs/vocabulary taken from the
   corroborated request. Preserve duplicate JSON keys, missing/extra IDs,
   noncanonical values, invalid JSON, output truncation and raw bytes. Match the
   claimed raw answer to a normal-stop native child terminal response and report
   all possible matches. Valid structure does not imply correct classifications.
5. Receipt access: literal access log claim, executed receipt() code and any
   returned receipt observation are separate fields. Access is not consumption.
6. Beyond-example extension: source-valid, native-matched helper request includes
   any ID outside q0001–q0004. Separate dispatch extension from a completed valid
   map covering those IDs. Report unique selected subsets by query/vocabulary,
   duplicate selection and ordinary alternative classification paths. Do not
   impose a complete 64-record/six-class map on every task or union semantically
   different queries into fictitious full coverage.
7. Observable incorporation: a recorded executed root cell reads the returned
   mapping and calculates a batch/global quantity, with linked tool observation
   where available. Record candidate static markers separately from manually
   supported data flow. This is not proof of hidden reasoning or that the map
   causally determined the final answer. Ambiguous or unprinted values are null.

One helper request may occur in several physical prompts of the same multi-turn
child invocation, or have multiple matching invocations. Retain the complete
candidate match relation. Report claim count, unique matched physical request IDs,
trusted child invocation/session count and ambiguity count separately. Do not
call all matching turns distinct helper dispatches. An unambiguous unique helper
API-dispatch count may be unavailable even when binary episode uptake is true.

Uptake is true when qualifying evidence exists, false only with sufficiently
complete capture establishing no qualifying request, and otherwise null. A
helper-signature native prompt without a valid corresponding claim is null, not
non-use. Missing/root-edited logs or partial traces can prevent a negative claim.
An episode with fully observed zero child calls can establish no native uptake
even without a helper log. Evidence of dispatch can survive a subsequent episode
failure; final-answer observability is classified independently. A helper result
without any call is not an invalid-map trial; map endpoints are not applicable.

## Primary contrasts, secondary answers and missingness

For each root and arm report planned 12, recorded, observable true/false/null,
and the full ladder. R−D is task-matched: 12 scheduled pairs, observable pairs,
gains, losses, ties, net gain and mean difference among observable pairs. Report
unknown pairs explicitly; never use a reduced denominator without naming it.
Provide six context summaries, each with the two task contrasts, phase and target
category. Root-by-procedure interaction requires all four D/R outcomes at a task;
retain remaining tasks as null. No token/record-level pseudoreplication, causal
mediation or user-conditioned treatment estimate. No powered significance claim.

Secondary strict final success uses exactly the inherited final parser/scorer,
independently checked against raw root reply and host gold: execution completion,
observable terminal, schema-valid integer, correct integer. Preserve valid-wrong,
malformed, complete empty/unanswered, truncated-final, infrastructure-null and
unrun/censored categories. Complete empty policy replies are zero under the old
contract, but remain explicitly empty; missing/failed execution is not scored
wrong. Preserve original metrics when adding orthogonal failure descriptions.
Report R−D, V−R and D/R/V−U secondary answer contrasts with the same pairing/null
rules. First-root finish reason, output length and structured-tool presence are
descriptive; malformed JSON tool syntax is not blank generation or transport loss.

Apply the design's practical thresholds only with the known/unknown range shown:
high uptake >=9/12, low <=2/12, and at least6/12 extending beyond the example for
the separate usability threshold. Unknowns that can change a classification make
it indeterminate. Context consistency matters. The prior decision table is a
resource-allocation aid, not automatic training, retirement or statistical proof.

## Cost, failures and publication

Count every retained physical root/child request and result once, including HTTP
errors, unsampled rejections, normal/length finishes and request-only tails.
Report attempted, returned and causally verified sampled calls separately. Use
actual wire token_ids for physical prompt/action totals and compare response
usage where available. Recover cached prompt counts from wire usage when present;
otherwise keep null. Report known sums plus missing-measurement counts, never
zero compute for unknown usage. Cached input is not subtracted from logical input;
uncached input is derived only where both measures are known. Token IDs/logprobs
are not retokenized or repaired; no probabilities or true entropy are invented.

Separate summed physical-call latency from concurrent wall time, phases, service
startup, collection, release and operation tails. Accepted caps override the
earlier idea's proposal: cumulative collection2400s, phases600/1200/600, work3480s,
owned3600s including120s cleanup reserve, outer3630s. No timer reset or successful
later rerun replaces a stopped coordinate. The inherited nano retry path can
consume time despite outer max_retries=0; quantify only recorded attempt/delay
evidence, not inferred hidden retry counts. Partial trace loss remains a cost and
observability limitation. Analysis must never retain GPU scheduling authority.

Publish REPORT.md, METRICS.json and SOURCES.json in this analysis namespace, plus
an immutable seal, after the terminal trigger. Preserve raw evidence pointers,
unknowns and disagreements with the frozen driver projection. The driver's AST
markers can omit unparsed code, its event dictionary can collapse duplicate IDs,
its physical cached-token field is hardcoded null and its turn counts are not all
physical attempts; independent projections will retain these distinctions without
editing frozen source. Compare an existing built-in summary only if available;
do not run it while holding or delaying the GPU owner's lock.
