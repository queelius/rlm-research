# Supplied maps and reducer availability: native audit

The helper-available treatment reduced strict final correctness on this small panel: native-map Python5/8 versus helper3/8; privileged dataset-map Python5/8 versus helper2/8. All32 final answers are genuinely available in the native traces; none is NULL. The result primarily diagnoses failure to use supplied resources: only one of16 helper-available endpoints actually called `count_labels`, and its successful call reduced a freshly acquired child map. No endpoint successfully used the helper on the supplied map. These cells therefore do not isolate pure reducer ability or the value of correct semantic labels.

I independently audited this scientific collector's raw evidence. I authored the earlier runtime plumbing, including the new-node driver/ownership adaptation, but did not author this study's scientific driver. This is not independent runtime implementation review.

## Acquisitions and concrete mechanisms

Four acquisitions each show exactly one actual c32 model call, two explicitly synthetic authored root transport calls, a successful native tool observation, and a strict complete16-ID/category JSON map. Actual child message, tool observation and frozen MAP.json agree in all four. Dataset-label agreement is62/64:16/16 train00,14/16 train01,16/16 validation00,16/16 validation01. In train01, q0005 is dataset “human being” versus child “entity”; q0014 is dataset “description and abstract concept” versus child “entity”. This is dataset agreement, not independent semantic adjudication. Native-map correctly scoped target counts are0/1 for train01 single/union versus dataset1/2; the other six query counts agree.

Selected findings below are backed by complete linked programs and native observations in ROWS.json; short IDs uniquely resolve there:

1. **Helper used once, on a fresh map.** Privileged-helper train00 union `ceb9ada6` first reclassifies and prints four4-record batches, repeatedly overwriting `labels`. Its first actual `count_labels(labels, requested_ids, "numeric value")` raises the helper's coverage ValueError because `labels` contains only the last batch. The next program reclassifies all16, then calls the helper with the correctly filtered eight IDs and observes1; final is `Answer: 1`. There are two entered helper calls, one successful, in this one endpoint. The helper catches an actual state/coverage error, but this is not successful use of the supplied privileged map.
2. **Availability often changes behavior into map enumeration.** Native-helper validation00 single `f30c76cd` prints four fresh batch maps and returns10 without a helper call or scalar tool result, versus native-Python `85f86bdf`, which loads supplied labels, repairs an incorrect metadata key, counts u00 correctly and observes2. Privileged-helper counterpart `26cb1c1b` returns7 after the same map-enumeration pattern, versus privileged-Python `280bdacc` observing2. This supports a behavioral integration problem, not arithmetic failure inside the helper.
3. **Stored labels can be loaded yet ignored.** Native-Python train00 union `198fc391` and privileged-Python `0a4d93cd` load `labels_json` but reduce `labels`, the fresh child's scoped map. Native-Python validation00 union `0bdaface` does the same. Correct final values here do not demonstrate supplied-map uptake. Conversely train01 native-Python union `2578338d` explicitly looks up supplied `labels_json[k]` over the scoped child's keys, observes1 and submits1: faithful supplied-map reduction can still disagree with dataset2.
4. **Apparent gains can be format or compensating errors.** Native-helper train00 single `71e6da90` gains strict correctness over native-Python `fc2cc8dc` because the latter's actual scalar0 is wrapped in explanatory prose. For train01 single, both helper finals equal dataset1 after four map-printing calls; the printed sole “human being” is q0010 (u01), while u00's dataset-human q0005 is classified “entity”. There is no executed scoped reduction. Correct1 can coexist with wrong scope and label disagreement; it does not establish recovery of the intended u00 classification.
5. **Proposed code is not executed code.** Privileged-helper train01 union `b3a846ed` ends with a fenced helper program instead of an answer, after four classification calls. Privileged-helper validation01 union `7678b701` also puts helper code in final prose and counts q0004, a u03 record, among its claimed union items. Neither executes the final helper snippet. Counting AST or text occurrence in those finals as uptake would be wrong.

Twelve endpoints encounter the actual `KeyError: 'synthetic user metadata'`; their later programs inspect the record and use the correct `user` field. These are recovered tool errors with genuine finals, not infrastructure NULLs. All six supplied-map integer reductions agree with the correctly scoped host reduction of that supplied map; no successful helper invocation reduces supplied labels. The negative result should not be summarized as “oracle labels do not help” or “count_labels is inaccurate,” because resource uptake is sparse and most branches acquire new labels.

## Ranked next tests

1. **Make supplied-state uptake observable and decision-relevant.** On the same matched small panel, compare the existing free root with a root continuation immediately after an authored load of `records`, full supplied `labels`, and correctly derived `requested_ids`; also include the exact host-authored reducer and direct-answer baselines. Keep oracle/native labels separate. Measure whether the root actually reuses the loaded map, calls the helper, obtains the scoped scalar and emits a strict final, alongside extra child calls. This diagnoses whether file discovery/state integration is the primary obstruction; it is an assisted continuation, not an end-to-end improvement claim.
2. **Separate helper instruction effects from executable availability.** With the state contract already understood, compare pure-helper file only, helper plus current instruction, and a short verified worked usage example; keep seeds and all other prompt text matched where possible. Require actual tool calls and coverage-correct arguments as uptake evidence. The present treatment's four-batch detour motivates this split; a larger accuracy run before reliable uptake has low information value.
3. **Train/test state maintenance and finalization separately.** Use complete demonstrations that retain full map state, filter `user` correctly, and emit an authentic strict terminal. Test transfer to another user subset/partition and nonzero as well as zero answers. Keep first-action imitation versus complete-action-plus-final comparisons explicit. The coverage ValueError/reacquisition and recovered metadata-key errors identify concrete intermediate behavior to target; do not equate passing a zero-answer example with the correct computation.

Advance a method only after actual supplied-map/helper uptake is demonstrated across source clusters with no uncharged reclassification, then replicate final accuracy effects. Retire the claim that this diagnostic by itself isolates map semantics or pure reducer correctness. No GPU run or source mutation was performed for this audit.
