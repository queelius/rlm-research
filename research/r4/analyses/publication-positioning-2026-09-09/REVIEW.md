# Publication positioning: preserve the evidence through the interface

Reviewed 2026-09-09 UTC. Bounded primary-source review of eight papers plus two official repositories. This is a positioning assessment, not a systematic novelty proof or a new experiment. Only the completed local reports listed in `SOURCES.json` support the experimental claims; running indexed SFT is excluded. The main session owns GPU operations and source acquisition; this review made no GPU calls or changes to existing reports, code, or queues.

## Strongest defensible angle

The strongest result is a controlled demonstration that **a fully valid batch response can lose most of the model's useful item-level accuracy, and an explicit output-to-input association can recover it with unchanged weights**. In the completed [anchor control](../anchor-indexed-followups-live-2026-09-09/ANCHOR_REPORT.md), identical ID-bearing task inputs and exact-cardinality decoding gave TREC64 38.2% versus 93.6%, and fresh SST64 60.1% versus 96.3%, for anonymous versus indexed outputs. Every response was valid. Small batches were already accurate. This makes output representation a decision-relevant bottleneck, beyond an invalid-output rescue.

The candidate paper question is: **When does a model's task competence survive the child → program → final-answer interface, and can training make it survive changes to that interface?** A useful eventual contribution would combine controlled boundary interventions, record-level evidence accounting, and crossed weights/interfaces. That complete contribution has not yet been demonstrated. Today the anchor result is a strong exploratory centerpiece; the root result is supporting evidence about a different boundary.

The [root-only RLVR comparison](../root-continuation-live-2026-09-09/REPORT.md) improves strict success 5/24 → 16/24 with an unchanged child. But the [first-action screen](../root-first-action-screen-2026-09-09/REPORT.md) finds usable first JSON requests 13/24 → 22/24 under an already supplied tool prefix. It supports interface adaptation; it does not establish learned decomposition or a causal syntax-mediated fraction. The selected checkpoint comes from one training run, and its six root-new contexts contain leaf-training-supported questions.

The promising modifications are therefore empirical interventions: a child return carrying a validated ID→label map; a program-visible record of consumed, missing, duplicated and conflicting IDs; and commitment of the computed aggregate together with its evidence map. Each ingredient is useful engineering, but the publication case would be a demonstrated interaction or failure explanation across these boundaries. Initially instrument coverage without forcing a preferred batching strategy; then test any enforcement as its own intervention.

## What not to claim

- No first use of IDs, typed wrappers, computed finals, RLM RLVR, or joint harness–weight optimization.
- No isolated attention/memory mechanism, learned arbitrary-ID correspondence, or equal-compute gain. Indexed64 emits about 3.2–3.3 times the tokens, and instructions plus grammars change together.
- No broad unseen-data generalization: the anchor has six/four context groups and one checkpoint; public SST is fresh to this study, with unknown pretraining exposure. Repeated seeds/items are not independent new test examples.
- No end-to-end faithfulness from high leaf accuracy. Only 1/24 indexed TREC64 and 0/16 indexed SST64 responses were entirely correct. Correct counts can also hide cancelling item errors.
- No claim that root training learned to choose Python or repaired the separate string/list bug. The first-tool prefix was supplied, and lexical batch-size assignments are not audited executed semantics.
- No hardware-efficiency conclusion from rollout wall time: serving order/concurrency were uncontrolled. The later wire audit recovers cached-token counts, but those counts are not measured physical GPU work.

## Two smallest discriminating experiments

### 1. Does an output ID help beyond forced grammar and added tokens?

Freeze the old child and eight new source contexts (four TREC, four SST), size64, two predeclared seeds. Run **anonymous versus indexed output × free versus exact-schema decoding** with identical task bodies and unchanged prompts within each representation across decoder modes: 64 calls. Add a token-matched anonymous-padding control in both decoder modes: 32 calls, 96 total. Place fixed task-irrelevant padding before each label using the same container shape and approximately the same tokenizer length as IDs; verify actual output lengths. Padding is an additional control, not a perfectly neutral intervention.

Primary readouts: unconditional correct item assignments, complete/valid responses, accuracy by position and exact aggregate correctness. Count malformed free outputs explicitly; do not compare only selected valid responses. Record actual input/output tokens, latency and stops. Use source-context paired effects as the inference unit. One loaded 4B on one A100, 15-minute collection cap, no training/checkpoints; immutable request/response records under a new experiment path. Expected execution is minutes based on the completed 600-call anchor, not a runtime guarantee.

If IDs remain effective freely and beat matched padding, promote a correspondence interpretation. If only schema-indexed works, narrow the claim to decoder-supported representation. If padding closes the gap, investigate extra generation/segmentation. Only after this discrimination should arbitrary-ID renaming and crossed old/index-trained weights be promoted as a reusable learned-skill study; use the frozen running SFT result as evidence when it finishes, without modifying its readout.

### 2. Does the root-weight gain persist when first-request syntax is controlled?

Cross **original versus selected root × existing versus syntax-constrained first tool request**, always using the same frozen child and supplied tool prefix. Use six fresh root context groups, two count queries and two seeds: 96 bounded episodes. Constrain only the tool-call envelope/JSON representation; keep the code string unrestricted and subsequent policy unchanged. Counterbalance order and repeat a small unchanged-policy block to estimate serving variation. Freeze verifier, budgets, schemas and sampling before collection. One 4B base with both root adapters, one A100, 45-minute cap; no retraining, checkpoint inputs immutable.

Measure strict success plus first-request validity, actual item coverage, child correctness where observable, aggregation errors and token/call costs. A remaining trained-root advantage under usable serialization motivates program/decomposition research and an independent training-seed replication. A substantially reduced gap makes interface compliance the practical lead. This factorial is an intervention on decoding, **not** a causal mediation estimate: forcing syntax can change the generated program. It is more informative than conditioning post hoc on valid calls. Source groups must exclude root-training/selection groups; if the fixed child requires leaf-training-supported items, disclose that scope explicitly.

**Immediate priority:** experiment 1, because it discriminates the strongest completed result with fewer calls and no new training. The present evidence could anchor a focused empirical paper after these controls and replication; a broad method paper remains premature.
