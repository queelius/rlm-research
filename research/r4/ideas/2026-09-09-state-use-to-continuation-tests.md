# Move from using evidence to deciding what to preserve

The active work remains corrective SFT, the accepted partition final-interface
backup, and the preparing leaf-role comparison. This note proposes successors;
it does not reserve data, alter a running study, or turn a conjecture into a result.

## What the neighboring projects add

The structured-decomposition note distinguishes report correctness, the answer
implied by those reports, and whether the parent follows them. It reports that
stronger instructions improved report following—including following wrong reports.
Its single-report revision screen found no wrong-to-correct report-tuple repair
under the tested action, despite some superficially better final answers. These
are that project's reported open-development findings, not pooled evidence with
our models or a newly audited reproduction.

The useful lesson for us is to measure whether a proposed action can help before
training a controller to select it. Agreement with a supplied map is not necessarily
dataset correctness, and an answer can be right without using the supplied map.
Our own [visibility audit](../operations/2026-09-09-allocation-5780/visibility-audit-report.md)
demonstrates why the executed data flow matters. The bootstrap program's principles
likewise favor immutable evidence, explicit decision changes and context-group
splits. We use that organization as inspiration without importing its unrelated
approval or implementation requirements into this GPU research session.

## Candidate1: can a compact artifact state replace the full history?

Our corrective-SFT capture now provides a useful precursor: real child responses,
multiple native Python actions, actual printed maps and exact pre-correction
prefixes. That is not yet a fresh-root continuation experiment.

The proposed question is whether the same fixed parent can continue accurately
from a compact, explicit artifact state at lower total cost than from the full
interaction history. First test a deterministic faithful state package before
learning summaries. It should contain the original goal, actual maps, source IDs,
coverage and unresolved work—but no host-computed answer, dataset labels, reward
or unseen verification feedback.

A minimal comparison could use all16 already planned held-out source states,
one fixed unchanged root, and three representations: full native history; a fresh
root with original goal plus faithfully externalized state; the same fresh state
with an explicit public metadata summary. That is48 new continuation endpoints,
four context clusters, with oneA100 and a proposed2400-second outer cap. It is a
feasibility envelope, not READY. Fresh paired seeds and exact source-state hashes
would be frozen before calls; every failed/unrun endpoint remains visible.

The key qualification is state equality. Every arm must have the same authorized
files, tool state and actual observations. The full-history arm must not secretly
retain a Python variable or map unavailable to the fresh root. Conversely, do not
give the fresh root a merged answer-bearing state that was never available to the
full-history arm. Any addition of accessible files must be common and disclosed.
Native graph construction must represent the changed history honestly, not merely
rewrite provider token IDs behind an unchanged recorded trace.

Charge all actual state creation, source acquisition, replay/reconstruction,
retrieval and new model calls. Historical shared acquisition is physical once but
fully charged to each hypothetical standalone pipeline. Report input/cache/output
tokens and elapsed time separately; shorter logical history need not mean lower
real cost when caching differs. No learned-state or depth-generalization claim
follows from a deterministic package working on16 short states.

Chained RLM already uses fresh roots with a compact summary, blackboard and durable
artifacts. Only its primary abstract was read for this note; the idea of restarting
from artifacts is not our novelty claim. A later contribution would require learning
which state remains sufficient across unfamiliar task structures and interruption
points, at measured cost. [Primary abstract](https://arxiv.org/abs/2608.05124).

Promote this pilot only if the ongoing controlled-continuation readouts establish
usable native states and enough variation to distinguish packaging. If a compact
deterministic package already dominates, use it as a strong baseline rather than
training a summarizer merely to create another checkpoint.

## Candidate2: test the value of an extra child call before learning when to ask

The visibility study contained six replacements of a supplied map. Those calls
were not uniformly useless at the label level, but they did not improve the target
counts. That is not a randomized estimate that all extra calls are wasteful.

A prospective branching screen can compare stopping with the current evidence,
reclassifying one fixed subset, and reclassifying an alternative subset from the
same real state. Sample the parent's subsequent policy again in every branch;
do not substitute a child result into a frozen final calculation and call that
adaptive downstream value. Compare against a fixed and random selection rule,
and charge every branch used to estimate the optimistic hindsight bound.

Use a small complete action table first, not only cases where host gold identifies
a wrong label. Promote controller training only if some available action actually
repairs answers, the benefit repeats under new samples, useful choices vary by
state, and information visible before the choice predicts them. If the same cheap
action wins everywhere, use that fixed policy. If extra calls mostly damage good
answers, retire the current revision action and propose a different one.

This remains lower priority than calibrating the leaf role and seeing the ongoing
SFT results. No task panel, action table, optimizer or GPU budget is frozen yet.
The existing counterfactual-credit question card and cited prior art remain the
authority for novelty limits; this note does not claim that counterfactual credit
or generic test-time revision is new.

## Candidate3: separate grounding from reduction rewards in future RLVR

An accurate reduction of a wrong child map should not be called a correct dataset
answer. Nevertheless, both measurements are useful. A separate synthetic state-use
training task could explicitly define supplied facts as its input truth and use
an exact reduction verifier; a real-data transfer task should keep dataset truth
and genuine imperfect child predictions distinct.

This may offer dense enough variation to teach multi-map computation before sparse
whole-task reward training. It is a different objective, not a retroactive reward
repair for current trials. Require a crossed transfer test with actual semantic
errors, held-out query operators and free-root evidence gathering. Otherwise we
may merely teach unquestioning obedience to a map. Do not train this branch if
ordinary clear instructions already solve it at ceiling.

## Ranking after the active studies

Prefer the next experiment that distinguishes the remaining bottleneck. A leaf
contract fix that removes code routing outranks more format-specialized SFT. A
controlled-only SFT gain calls for a test of reaching useful states from scratch.
A free-root gain calls for a fresh context/seed replication before increasing
training. Poor report composition with valid finals calls for representation
comparisons with identical facts—not an automatic communication-loss conclusion.
