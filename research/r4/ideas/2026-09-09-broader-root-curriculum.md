# Teach aggregation across documents, then test what transferred

Status: data/design candidate, 2026-09-09. No training recipe, model choice, runtime qualification, acceptance, or launch is frozen here. The accompanying [candidate data](../sidecars/root-curriculum-data-v1/README.md) are outcome-independent; existing experiments and checkpoints remain untouched.

## What uncertainty this addresses

The [completed first root campaign](../analyses/root-continuation-live-2026-09-09/REPORT.md) improved5→16/24 on six held-out compositions made from questions already supervised into its child; the parent reports a subsequent6→20/24 paired check on those same compositions. That second number is motivating context supplied by the parent, not freshly audited here. These are useful orchestration signals, not demonstrations of general adaptive decomposition. The independent seed's small validation curve remains variable; its later continuation is ongoing at this proposal's cutoff. No latest outcomes were read to allocate these data.

Four repeated root-training contexts leave two competing explanations: the root learned a reusable aggregation strategy, or it learned a narrow routine tied to familiar sizes, categories, and documents. More optimizer updates alone would not separate them. This proposal expands documents and query targets while keeping the underlying count operation stable, then separates composition, requested-category, length, and task transfer.

## Ranked options

1. **Recommended next run: broaden documents, sizes, and requested categories for 16 updates.** Use 24 new training contexts: eight each at 16, 32, and 64 records. Each proposed update uses three contexts, one per size. Revisit each context exactly twice, with a different requested category. Four categories (human being, numeric value, entity, location) each occur in 12 of the 48 scheduled task groups. Eight fresh rollouts per task would give 24 trajectories/update and 384 total, improving the chance of within-task mixed rewards. This is a proposed rollout allocation, not a frozen learning choice. Evaluate on entirely separate source-question groups. This asks whether the existing learning signal survives broader root experience; it does **not** isolate breadth from the additional updates or rollout budget.
2. **Best causal comparison if the first option is informative: narrow versus broad at matched 16-update opportunities.** Start both from the same authenticated original root and keep one child, harness, sampling, reward, and optimizer recipe fixed. Compare the 24-context schedule to four repeatedly sampled training contexts selected without outcomes from the training pool; never move a validation/transfer document into training. Match 384 attempted trajectories and report actual eligible groups, tokens, updates, and service time rather than call the runs compute-matched. Use the same predeclared transfer tasks and paired seeds. Two training campaigns cost approximately twice as much; defer until there is enough mixed reward and transfer headroom to justify it. This is the experiment that can attribute a difference specifically to breadth.
3. **Later operation-transfer curriculum: whole-context counting versus counting after a visible metadata filter.** Use the same public Date/User fields to ask counts for a specified user or date range, with host-derived exact answers. This tests input selection and aggregation, not merely recognition of different category names. Do not implement it together with option 1: it changes reward/task structure and needs its own frozen target-mask/gold audit. SST counting is a cheaper zero-training domain readout now; mixed SST root training would destroy that zero-shot task-transfer interpretation.

## Suggested readout, not yet a launch protocol

Keep one child fixed throughout a campaign; prefer the previously qualified capable child for an initial root-only attribution. Starting from the original root cleanly measures the new curriculum. Starting from a selected learned root instead asks about continuation and must be named as such. Do not use transfer scores to choose either option. Bind exact weight and optimizer lineage after parent review.

Monitor validation at updates0/4/8/12/16, using eight contexts and two fixed trajectory seeds (16 episodes per checkpoint), with requested categories balanced across the four training targets. Record all checkpoints and save adapter/Adam/RNG/input cursor after every actual update. Prefer fixed-final update16 as the primary comparison and show the entire validation curve; if a validation-selected checkpoint is desired, freeze its tie rule before training and evaluate it separately. An early stopped checkpoint is partial, not “final16.”

Smallest paired final panel, original root versus fixed-final root, same child and physical inputs:

- Composition: six64 contexts × one trained and one reserved query target × two seeds =24 pairs. Alternate HUM/NUM and DESC/ABBR across context index without inspecting answers.
- Length: six128/256 contexts × one trained query target × two seeds =12 pairs, reported separately by length. The two256 contexts are a stress probe, not precise evidence across many long documents.
- Child-test-exposed: three32 contexts × two trained targets × two seeds =12 pairs. This96-question stratum is small and historically evaluated by leaf models.
- Optional child-validation-exposed: eight32 contexts × one trained target × two seeds =16 pairs; report separately because child checkpoint selection used this source partition.
- Optional SST: three32 contexts × positive count × two seeds =6 pairs. Negative and positive counts complement one another and are not independent tasks. This is root task transfer with a publicly pretrained-capable child, not evidence of unknown sentiment concepts.

Primary outcome is strict correct aggregate count per planned episode, alongside observed/admitted coverage. Also report conditional correctness among observable episodes, invalid final submission, infrastructure/censored episodes, terminal tokens, root versus child calls/tokens, recursion coverage, child batch sizes, and per-call alias evidence. Recovered provider errors remain diagnostic events, not automatic null episodes. Fresh training-seed rewards are unpaired across updates. Shared-input stochastic trajectories are not deterministic replay.

Do not reward a forced recursion shape. Preserve root-only native action credit, masked observations/child text, fresh rollout generation per update, and persistent optimizer state. Measure whether successful policies actually inspect records, choose useful child chunks, validate alignment, and sum counts. A short fixed Python routine that transfers well is useful orchestration but not proof of adaptive strategy selection. The filtered-count option is a later discriminating test of adaptivity.

## Compute and decision gates

Provisional one-A100 shape: serialize inference and one full-batch root-only update for each of16 fresh generations, retain existing qualified role/lifecycle boundaries, and checkpoint every step. With384 training episodes,80 monitored validation episodes, and96 mandatory paired evaluation episodes (140 with both optional strata), budget roughly3–6 GPU wall hours including service reloads. This is an engineering estimate from the prior multistage campaigns, not a measured promise; long recursive tails and128/256 contexts can dominate. Propose a6-hour overall cap and explicit per-stage caps, with partial checkpoints preserved. Parent must approve a concrete runtime/token envelope after examining the current campaign and source lengths; data preparation is not a backend fit qualification.

Before promoting: confirm at least12 of16 planned updates actually occurred with valid mixed groups; otherwise call the learning exposure inadequate. Favor the breadth comparison if improvement appears across at least4/6 new composition contexts, has positive net paired change rather than one lucky seed, and does not reduce observable coverage. A proposed practical signal is at least+6/24 composition successes plus a positive length-panel change; these are exploratory decision thresholds, not significance tests. Require independent training-seed replication and the narrow16 control before attributing the benefit to breadth. A gain confined to trained targets/short contexts revises the claim to narrow aggregation. Flat validation/transfer with valid substantial updates and a competent child retires this particular scalar-count curriculum, not RLVR generally. Many null groups or endpoint failures demand a feasibility correction, not more blind training.
