# Counterfactual operator signatures — design only

**Question.** Can paired terminal answers reject known pooled substitutes without process supervision or supplying a gold map? Yes, as a finite diagnostic: passing cannot prove the executed algorithm. No implementation or GPU run is authorized here.

**Evidence.** Full reads of the completed [composition audit](../analyses/root-operator-composition-transfer-live-2026-09-10/REPORT.md) and [interface audit](../analyses/root-operator-task-spec-interface-live-2026-09-10/REPORT.md) find no faithful composed successes, despite scalar matches. Read/recount of all24 [ANTI_COINCIDENCE rows](../../../ARTIFACTS.md#unpublished-files "Not published: ../sidecars/root-operator-task-spec-interface-v1/inputs/ANTI_COINCIDENCE.json"): any listed confuser agrees on17/24; threshold-on-pooled matches6/8 threshold tasks, pooled-A matches2/8 maxima, pooled-B matches3/8 conditional tasks. Positive weight changes alone cannot resolve two maximum/threshold contexts with ≤1 A-bearing user, or three conditional contexts where every B owner already has A. Thus recommend **query parameters plus label-blind weights**, not weight-only invariance.

**Smallest comparison:48 native roots.** Retain all eight exposed16-record contexts × three compositions × original/counterfactual. Same fixed24/c32, original native U interface, no card/helper/maps/grammar/forced batching. Two controls only: contemporaneous originals; offline deterministic four-confuser signatures (not model solutions). One fresh paired sampling seed/block; balanced original/counterfactual dispatch. Counterfactuals keep texts, public IDs, owners, record order, operator and all-scope. Assign each record weight `1 + int(SHA256(namespace|context_id|record_id),16) mod 7`, shared across its three counterfactual questions; never optimize weights against labels.

Select counterfactual A from all six TREC categories; conditional questions consider all30 distinct A/B pairs. For other families, unmentioned B is fixed by the YAML rule, never optimized. Threshold candidates are1,3,5,7,9. Using host labels **offline**, maximize fixed confusers rejected by the original-plus-counterfactual answer vector; then counterfactual-only rejections; then prefer original categories, threshold nearest5, and lexical order. Freeze candidates, tie-breaking, answers and residual coincidences before sampling. This is label-conditioned **targeted challenge selection**, not unconditioned accuracy or fresh-context transfer. Retain all24 pairs, zeros and unresolved collisions; no rerolls. Weights are label-blind; selected questions are not.

**Tiny example (illustration only).** A weights: u0 has3+3, u1 has6; B weights: u0 has2, u2 has5. At threshold5, requested `(user-count, max, conditional-B)` is `(2,6,2)`; pooled A=12, pooled-threshold=1, pooled B=7, A-record-count=3. Multiple terminal numbers reject these substitutes without revealing any algorithm or labels to the root. A different wrong program can still match this finite signature.

**Metrics and limits.** Strict authenticated `Answer: N`, all48; report individual and both-correct pair rates, eight context means, NULL bounds, and each confuser's individual/pair false-pass rates. A sampled answer vector matching a confuser is compatible with—not proof of—that operation. New child prediction errors can spoil a correct operation; retain actual child outputs for separate posthoc map-consistency, never repair primary answers or inject labels. Different queries/weights change difficulty and token history, so no pure weight causal effect. All inputs are previously root/child-exposed; current queued studies remain unread and unchanged.

**Budget/decision.** One A100,1800s outer/1650 work/1770 owned,180 startup/1440 collection/30 harvest/120 cleanup/30 margin;4 workers,180s episodes,2048/8192 caps, no retries. Freeze all48 even if time leaves NULLs. Before GPU, require ≥16/24 pairs reject all four fixed confusers, else retire this proposed battery without reselection. Afterward, low paired pass with confuser-consistent answers supports an operator-binding diagnostic; high pass rejects only this confuser set, not certifies execution. Counterfactual-pair RLVR is a separate unapproved future proposal: no reward changes or reuse as protected evaluation, and no conjunctive sparse reward without a feasibility check.
