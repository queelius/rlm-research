# Acquired evidence accumulation: proposed32-root package comparison

Design only, after the sealed scale audit; no implementation/GPU approval. This is an architectural interface question, not a new algorithm or novelty claim. MAIN selects the exact intervention before code is written.

## Question and default

Does automatically retaining **structurally validated decoded predictions**, whose actual acquisition provenance is independently audited, through the decoder already used by the root improve faithful computation at128/256 records? Scale had complete disjoint256-record acquisition in two paths, but repeated `chunk_map = strict_map(...)` assignments overwrote earlier batches. None of24 paths verified executed accumulation. The earlier optional canonical loader was used1/24 and never reloaded; merely advertising another lookup may again fail to exercise the mechanism.

Default: all sixteen fixed large scale blocks (four parents ×128/256 ×count/weight), one fresh paired seed each, two contemporaneous arms=32 roots. Same fixed24/c32, exact records/order/IDs/query/gold, external files, native coding role, optional tools,2048 action/8192 context,.5 temperature/top-p1. No forced width, child call, decomposition, reducer or retraining. These parents are now exposed, not a fresh generalization test. Use all large cases, not the two favorable overwrite examples. Preserve all nonzero golds and predeclare baseline distribution before launch without reranking.

**BATCH control:** current strict decoder validates the returned child JSON against the current requested IDs/canonical categories and returns an ordinary dict of that batch.

**CUMULATIVE treatment:** identical validation of the current raw string and requested IDs; after successful validation, deposit its labels in an episode-private module store and return a fresh ordinary dict snapshot of all accumulated decoded labels. A subsequent assignment to the same model variable therefore retains older IDs. The store never invents labels: every entry comes from a model-submitted decoder input, but that input can itself be a copied, edited or fabricated literal. Such entries are not automatically called acquired evidence. The module is not a task solver: no records selection, query/scope/operator/weights/gold, classification, aggregation or final answer. The root may ignore, corrupt or replace its returned snapshot; only another qualifying decoder call reconstructs the stored snapshot. No automatic error recovery/retry or hidden namespace repair. Module privacy is conventional Python encapsulation, not a sandbox guarantee against deliberate introspection or reload.

This explicitly **changes return scope**, not the input validation rule. It is not a drop-in public API compatibility claim: after two batches, returned keys may exceed current requested IDs. Treatment's truthful API sentence must say this. The control retains batch-local wording. Common decoder-call bookkeeping is present in both arms but does not affect returned objects. This is a state/return-contract plus description package, not a pure memory-capacity intervention or learned decomposition claim.

## Admission, conflicts and real feasibility gate

The store starts empty per episode. The selected minimal implementation is **structural decoder admission plus independent provenance audit**, not online authenticated-call admission. It copies only values supplied to successful strict_map calls; no historical-map prepopulation, labels from host/gold, partial deposit, unseen-ID default or automatic acquisition. Existing validation rejects malformed/truncated JSON, duplicate keys, missing/extra current IDs and invalid categories; a fabricated but structurally valid map remains admissible exactly as in the control. Do not advertise the store as guaranteeing genuine acquisition.

Source inspection establishes a narrow working seam: `adaptive-filter-pilot-v1/batch_contract.py` is already a task file; strict_map accepts only `(raw, ids)` and has no provider/request identity. Scale's qualified fixture uses `from rlm.api import run as rlm` independently, then passes `child.answer` to that decoder. A genuine-call registry would require interposing on this separate native API and transporting IDs across that boundary. Its reliability is not established by reading the helper or by a synthetic example. The default therefore modifies only the isolated task-local decoder file and common call ledger; no native API wrapper, bootstrap import override or new transport is required. This is MAIN's explicitly permitted simpler scientific intervention, not an unannounced downgrade. An online registry is deferred, not a launch dependency.

Before READY, run the existing actual ACP/IPython authored two-child fixture with disjoint batches and repeated assignment, verify batch versus cumulative returns, and verify attempted mutation of the returned snapshot does not change a later snapshot. Add a valid fabricated-input fixture that is accepted and labeled synthetic; it must never be claimed as sampled evidence. Actual run provenance comes from retained native request/response tokens plus executed decoder-call raw input/IDs/return snapshots and observations. Classify each committed entry as exact prior native-child-derived, literal/copied or transformed, contradictory, or unknown; preserve timing, ambiguity and repeated-call identities. Exact content agreement alone is insufficient to prove causal use when the program is ambiguous. Independently audit all newly physical calls, including those never decoded. No sampled program reexecution.

Conflicts: latest successfully validated **decoder input** wins in serialized synchronous commit order, with old/new values, input hash and commit order recorded in the common ledger; actual provider identity is attached by the offline provenance join where established. Never pick by dataset correctness or majority vote. Duplicate identical inputs add no coverage. Failed validation deposits nothing. Root-edited dict snapshots cannot mutate stored history; explicit module reload/tampering remains observed model behavior, not silently repaired. A never-decoded ID remains missing/KeyError, not a fabricated default.

Return an ordinary dict, not a non-JSON-serializable proxy. Do **not** abbreviate repr, suppress existing prints, silently externalize histories, alter context limits, or compress observations. Existing `json.dumps(chunk_map)` may now print a growing cumulative map and increase context cost; measure this tradeoff. A compact state-view experiment would be a distinct next lever if persistence works but printing dominates.

Alternative, not default: keep strict_map's current return exactly unchanged and expose a separate read-only accumulated lookup. It has cleaner backward compatibility but reintroduces optional-interface uptake, so does not directly address observed repeated overwrites. If MAIN prioritizes that estimand, predeclare it as an offered-interface study rather than substitute it for automatic cumulative returns.

## Oracle and decisions

An oracle child is **not necessary in the first32**: actual acquired maps and observed reductions already separate arithmetic/state fidelity from semantic correctness. Do not replace wrong c32 labels or manufacture a controlled-state score after seeing failures. If treatment produces faithful accumulated reductions but dataset gains remain capped by wrong acquired labels, a separately approved paired oracle-child study on **all the same large blocks** can estimate that ceiling. Label it oracle/scaffolded, keep its denominator/cost separate, and never present it as the normal c32 result.

Exploratory promotion rule: intervention actually returns multi-batch state in at least two parent clusters and produces at least four additional faithful requested accumulated reductions per16 treatment tasks, with no loss of native availability; practical promotion additionally requires positive planned strict-dataset difference. These are decision thresholds, not statistical significance. If fidelity improves but only child-semantic errors prevent accuracy, pivot to source-label quality. If cumulative snapshots are returned but abandoned/wrongly reduced, prioritize task-spec/error-recovery training. If expanded map printing causes context failures, test a separately declared compact state interface. If the automatic path is barely exercised because requests fail before validation, this free-run experiment has not tested persistence; do not generalize its null result to a functioning state store.
