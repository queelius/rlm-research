# Labels-only leaf output with caller-owned binding: conditional design

2026-09-10. Design only; no implementation, input selection, GPU or queue change authorized. This is a bounded research proposal, using the brainstorming approval gate. Default: a32-call MNLI transfer/cost screen, lower priority than the pending fixed-output mechanism study—not an assumed improvement to deploy.

## Why test it, and why not expect it to win

Separating semantic prediction from ID serialization is ordinary batch demultiplexing. A caller can attach its immutable ordered IDs to a complete ordered label array, but this only guarantees bookkeeping, not that label_i describes record_i. A48-label array can silently misbind every prediction while looking structurally perfect.

We already tested the underlying plain-label interface on released Qwen3-4B: classifier/no-tools exact decoding gave matching218/256 versus plain123/256 on four AG/SST contexts, all contract-valid, matching better in all four. [Role/tool audit](../analyses/leaf-role-tool-live-2026-09-09/REPORT.md). Dense label-first is not new; [sparse order](../analyses/leaf-sparse-cue-order-main-review-2026-09-09/REPORT.md) and [same-record phase](../analyses/reminder-phase-live-2026-09-09/REPORT.md) already show local matching-ID benefits and their movement across generated labels. Removing tags may remove useful reminders, not merely redundant serialization.

The new16-context MNLI replication gives matching611/768, shifted298/768, alien618/768, all valid. Shifted outputs favor the wrong named record on361/530 unequal-gold positions. That supports avoiding misleading aliases, but alien≈matching does not imply no emitted alias≈matching. [Independent report](../analyses/leaf-mnli-new-context-alien-correspondence-live-2026-09-10/REPORT.md). The proposed screen would extend an already-run interface comparison to MNLI and measure practical cost; no new demultiplexing or order-control novelty is claimed.

## Metrics, admission and decision

Primary: end-to-end strict caller-ID→displayed-label correctness /768 planned records per arm, admitting only authenticated complete contract-valid native outputs. An observed malformed cardinality/enum/output contributes known0 for its entire batch; missing/unauthenticated native output stays NULL with bounds and separately known operational failure where appropriate. Do not attach any IDs to malformed output. Report availability, contract validity, conditional positional label accuracy, perfect-array count, confusion/count-vector diagnostics and per-position errors separately. Forced/attached ID fidelity alone is not a semantic success metric. No post-hoc shift, permutation or “named” rescue.

Use16 paired context means, four-genre breakdowns, context signs and stratified bootstrap intervals; records/seeds are not independent replications. All physical attempts, HTTP returns, authenticated completions, input/output/cache counters, unknown usage, latency and owner/service wall time are retained. Billable cost is unknown. Report output-token reduction and total-token reduction separately, plus correct labels per1,000 total tokens as a secondary ratio—not a substitute for accuracy. Do not subtract attached-ID bytes from downstream root input: a future RLM root would still consume the full reconstructed map.

Promote only to a separately approved fixed-root integration test if observed operational accuracy loss is≤2pp, no availability/cardinality disadvantage,≥30% output-token reduction and≥8% total-token reduction, with paired95% lower bound above−5pp. These are pragmatic exploratory thresholds, not certified noninferiority. Retire this exact48 labels-only recipe if accuracy loss≥5pp or lower availability eliminates savings; do not add epochs merely to rescue it. Intermediate/uncertain results are inconclusive, not success. No root study is included in these32 calls: root final accuracy, genuine child-call uptake and downstream consumption require subsequent contemporaneous root trajectories with identical returned-map schema and freely chosen batches.

## Relation to fixed-output48 and training

Pending fixed-output48 holds requested aliases/output grammar fixed while changing visible IDs; it addresses referent association. This proposal changes the output representation/history and thus answers a different engineering question. Do not modify either design based on selected contexts or reuse prior matching responses as controls. Prior role/plain failure lowers this proposal's priority even if fixed-output proves interference.

A promising later training question is whether group-disjoint supervised batches with label targets and varied label-blind display order learn reliable positional semantics at widths16/32/48, evaluated on frozen unseen premise groups and compared with matched tagged SFT. Dense correct labels are available, so SFT is the cleaner first test than policy-gradient RL under an exact grammar whose forced ID tokens carry no semantic choice. Match examples/label exposures and report optimizer steps/target-token differences; do not train on this development panel, pick best checkpoints on it or mix protocol changes into an optimization-dose claim. Reward-filtered/rejection-sampled SFT is still SFT, not policy-gradient RL. Actual constrained-policy RLVR would require sampled-action log probabilities under the constrained distribution, a declared semantic reward and on-policy updates; no evidence here establishes that its extra machinery is preferable.

## Primary prior art and read depth

[Batch Prompting (EMNLP2023 Industry)](https://aclanthology.org/2023.emnlp-industry.74.pdf), read Figure1,§2 and§3 setup/results: ordered batched inference and positional identifiers already support matching/parsing; experiments include MNLI, mostly Codex/few-shot/batches2–6. It does not establish that removing IDs is harmless at48 under a4B constrained decoder.

[BatchPrompt v2](https://arxiv.org/html/2309.00384v2), read§§1–4 and AppendixB prompts (not all appendices): order-dependent batch predictions, indexed outputs, permutation/voting and adaptive dropping are prior art. Its reported main token savings exclude generated output tokens; our question measures both and uses no ensemble/drop. Omission warnings reinforce strict cardinality admission.

[Constraint Tax v1](https://arxiv.org/html/2605.26128v1), re-read§3.2,§4,§6.3 (earlier full-note reading linked below): validity is not correctness; its calendar delayed-packaging control deterministically reserializes a prior answer rather than demonstrating a new sampled policy. That supports attribution discipline, not a guarantee for labels-only or external binding. [Earlier bounded literature note](2026-09-10-schema-wording-constraint-tax.md). No repos, code or assets acquired for this proposal; literature is primary-linked, with no novelty-certification claim.
