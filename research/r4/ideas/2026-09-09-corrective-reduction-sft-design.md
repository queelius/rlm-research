# Corrective state-use SFT after genuine map observations

Status: feasible proposed design, not implemented or READY. No corpus, training, model service or GPU job is created by this note. MAIN retains experiment acceptance and scheduling. This proposal does not duplicate the already-preparing root-example-map-visibility diagnostic: its intervention is supervised root actions at a later native decision point, with the evaluation harness held fixed.

## Recommendation and falsifiable question

Recommend Option A first:32 native captures with varied, genuinely executed map-producing prefixes; supervise the next Python action that reconstructs the visible map and performs the requested scoped count. Compare unchanged low66c, corrective-action SFT, and a matched first-action-only SFT control. A small forward-only objective/cost check precedes the full corpus and optimization. Option B samples training-only prefixes to improve state-distribution matching, but is a second step if A's controlled-continuation improvement does not transfer to free roots.

Question: does changing the supervised decision from “start classifying” to “use these actual observations to execute the scoped reduction” improve held-out query compositions and actual executed reduction, without relying on already-saturated scalar copying? This isolates corrective state use. It does not promise adaptive decomposition, semantic-label correction, or general RLM gains.

Evidence: the [complete-SFT audit](../operations/2026-09-09-allocation-5780/complete-sft-audit-report.md) finds8/16 unchanged versus1/16 in either trained arm, with terminal contribution only2.0e−8 on the first update. In12/16 trained readouts the visible labels support the correct scope count but the final is wrong;15/16 trained episodes finish after maps instead of a scalar. The [supplied-map audit](../analyses/root-supplied-map-reducer-live-2026-09-09/REPORT.md) finds only one actual helper-user among16 helper endpoints and no successful helper reduction of supplied labels. Supplying a resource, predicting its presence, and actually using it are different endpoints.

## Option A — authored prefixes, state-independent corrective targets (recommended)

Use32 examples = eight16-record training contexts × two queries × two execution layouts. The initial root programs are explicitly operator-authored. Every semantic classification is an actual c32 model request in the qualified native runtime. Layout1 classifies/prints one16-record map. Layout2 uses four successive root tool actions to classify/print four4-record maps while overwriting the last-batch variable, matching both the state and multiple-observation history of the observed failure pattern. Do not collapse these into one tool observation. Hash-assign harmless variable names such as `labels`, `batch_labels` and `categories`; none is a hidden required teacher variable.

The next authored action must work from information actually visible at its native prefix. Its recommended form explicitly reconstructs a fresh `by_id` dictionary from the actual printed ID→label maps, reloads standard records.json, selects IDs using the current query's user set and the real `user` field, and evaluates a Python count of the exact requested category. The map literals come only from actual child/tool observations, never dataset labels. Reconstructing visible evidence makes the target valid when sampled roots have overwritten `labels` or used other variable names. Do not silently install an `all_labels` accumulator, labels file, parsed query object or other teacher-only runtime state that free roots do not have.

The corrective program's map reconstruction may copy label tokens, but its scope selection, merge and reduction are the target behavior. Measure those code-line losses separately from copied payload and syntax. Train the complete current corrective action suffix, including its native tool envelope and EOS; do not claim that high loss on payload spelling alone demonstrates learning scope. Data literals must map back to the exact root-visible observation spans. If any required ID is not visible, a complete-map correction is not valid and must not be fabricated.

Within the32 layouts, preassign eight examples to append a real invalid metadata lookup after printing the map(s), producing the observed `KeyError: 'synthetic user metadata'`. The correction reloads records and uses its actual schema. The error is deliberately authored and actually executed; label it as such. It is not a naturally sampled policy mistake. Keep this variation orthogonal to query and map layout. If mixed stdout/error formatting fails to preserve required map visibility, stop that corpus variant and retain the failure; do not manufacture an error string or quietly omit the difficult row.

After the corrective action actually executes, capture its scalar tool result and an authored strict `Answer: N` equal to that scalar. Retain wrong-against-dataset scalars exactly. The final closes and authenticates the demonstration but has **zero training weight** in the proposed corrective arm. No gold-based correction, success filtering or automatic finalization is added to free evaluation.

The prefix includes every actual system/user message, initial root action, child calls/returns, printed maps and any real error. They are all conditioning tokens with loss−100. Only the current correction tool-call suffix receives CE. Synthetic authored-provider logprobs are transport placeholders and never become RL likelihood/reward/advantage fields. The child is fixed c32 and excluded from optimization.

Advantages: predictable32-example yield/cost; targets remain valid without hidden REPL variables; directly attacks observed map→scope-action failure. Limits: authored states need not be states sampled roots reach; literal map reconstruction is one explicit correction strategy; source-token copying may dominate unless the prospective objective check rejects that failure. A controlled-prefix effect alone is not a free-root improvement.

## Option B — sampled training prefixes, then authored correction

Use the same32 training task/layout coordinates but let unchanged low66c generate the prefix in the existing native runtime for at most four root actions and four actual child calls. Pause at the first predeclared eligible next-root boundary: full requested-ID map coverage visible in returned tool observations, or a metadata/coverage error with sufficient earlier visible labels to make a corrective target valid. The pause rule uses state/coverage, not dataset correctness. Record all attempted coordinates, early finals, missing coverage, costs and eligibility; never resample until success.

For an eligible state, create an authored correction using the actual transcript as in A, then run it in that same live native REPL. Previous root actions are genuinely sampled and retain their raw provenance, but remain masked. Correction and final are authored SFT targets; this is not on-policy RL or sampled successful-trajectory training. Do not use completed evaluation traces as training examples. With only32 starts, fewer than32 eligible states is plausible; if fewer than24 qualify, stop and report yield rather than replacing them. A later64-start version requires a separately frozen cap and remains a state-conditioned subset.

Advantages: addresses reached-state mismatch directly; can teach recovery after genuine sampled errors. Costs/limits: requires a collector pause/override at an internal root decision boundary, higher and variable child/runtime cost, and explicit selection-by-state accounting. Do not splice a continuation from another process's REPL, replay guessed variables, or transplant a root prefix into a fresh container without faithfully reproducing its history. Existing scalar-only capture does not already implement this. Choose B next if A passes controlled correction but not free-root transfer; do not spend the initial two-hour pilot building a general intervention framework.

## Data, controls and readout

Raw-source feasibility: existing root-interface-sft-v1/prepared-v2/PUBLIC.json has384 record groups in its eight explicitly training contexts (four32 and four64 records). Prefer a label-independent128-group subset from that training-side raw pool, remixed into eight16-record contexts. Reuse of raw historical training groups is declared; it is not fresh-root data. Before READY, enumerate exact normalized-group exclusions against every readout/reserved catalog, including complete-SFT/supplied-map/example-visibility panels and any newly reserved sibling-study panel. Do not turn those64 readout groups or their traces into training data. If the post-exclusion training pool cannot supply128 groups, revise the proposed population explicitly before freezing; do not silently borrow evaluation groups.

Freeze training context membership and query composition before actual child labels/target counts are observed. Train single-user queries for u00/u01 and two-user union queries for u00/u01 or u02/u03, assigned by context hash. Balance HUM/NUM target category by context index, not by outcome. Preserve zeros and nonzeros without acceptance filtering. Train examples differ in layout but share their source/query block;32 examples are not32 source-independent tasks.

For the first bounded readout, keep the existing64-group four-context readout panel entirely out of the new training pool. It is already evaluator-exposed and must be labeled as such. Freeze new query compositions: u02-only and the u00/u02 union, with two seeds per context (16 endpoints/root), plus matched u00 and u00/u01 regression coordinates (16 endpoints/root). New user-set compositions are prospective; raw sources are not newly unseen to the research process. Reserve no claims of virgin benchmark performance. A later replication needs independently reserved sources and more clusters.

Primary readout is32 free-root endpoints per policy under the same fixed native prompt/harness; no authored producer or automatic correction is supplied. Keep optional child access and count all calls. Compare strict available correctness and NULLs, executed scoped reduction, actual map coverage/data flow, scalar observation, metadata/coverage repair, reclassification count and full token usage. Final-value agreement alone is insufficient. Separate new-composition16 from regression16, and cluster by source context.

Secondary mechanism readout uses16 held-out controlled-prefix continuations per policy with the same two state layouts, all constructed from actual child calls on the readout-only sources; these continuations are evaluation-only and never train the next model. An exact authored corrective action on those states supplies a map-consistency ceiling, not learned accuracy. Host dataset correctness remains a separate score; actual-map errors are retained. Controlled and free readouts are separate rows/claims, not pooled.

The two SFT arms start independently from the same low66c adapter and fresh Adam: correction-only versus first-action-only from the same32 episodes. Both have equal example-mean token-mean CE mass1 and four fixed updates. The control trains only the first actual producer action at its original native boundary; subsequent producer turns are retained as masked history for the corrective target. Thus each arm supervises one contiguous current-action suffix per episode, at different decisions, without disguising four disjoint turns as one target. No target token is taken from evaluation. Token counts/forward cost differ and must be reported; matched steps/example mass are not matched FLOPs. Unchanged low66c is the mandatory baseline. Do not add another terminal-only arm whose objective is already saturated.

## Prospective objective/cost gate and two-hour envelope

First capture eight fixed training examples, crossing both layouts and query types. Preserve them as the first eight members of the32-example corpus, not a separately selected easy set. Verify that the exact next-root prefix re-renders to native wire IDs and the correction executes from that state to an authentic scalar. Measure unchanged-root teacher-forced NLL for initial action, corrective action, scope/merge/reduction lines, copied map payload, and final scalar format. Forward-only probing does not update weights or sample dataset correctness.

Prospective engineering gate: at least four of eight examples must have mean NLL≥0.1 nat/token on the scope/merge/reduction code spans, and median whole-correction NLL≥0.05. These are declared practical floors against a near-zero copying objective, not validated scientific thresholds. The contribution cannot be entirely isolated to map literals or boilerplate. Require all target masks/current-action boundaries correct, no truncated8192-token prefix, actual code execution/observation agreement, and a measured cost projection within the remaining budget. If these fail, stop before large capture/training and revise the target; do not compensate with more epochs or a higher coefficient. Freeze the result and full32 corpus before either learned arm trains. A single variable-length-prefix/token-loss utility must report these spans without changing which tokens receive the declared training loss.

Retain qualified Qwen3-4B base, rank8 FP32 LoRA trainables/BF16 base, c32 child, AdamW lr1e−4/weight_decay0, clip1 and four fresh updates to isolate supervision position against the prior recipe. Save adapter/config/Adam/RNG/cursor/ancestry after every complete update; interrupting accumulation yields no partial optimizer step. Fixed checkpoint4 is the readout candidate. No post-hoc best epoch, extended epochs or silent fresh-Adam “resume.” If interrupted, record a separately accepted continuation from the last complete checkpoint.

Proposed hard envelope on one A100: outer7200s; work6900s;180s owned cleanup and120s parent margin. Stage ceilings clipped to the shared work deadline: capture1800s total (including eight-example prefix probe capture), forward-only objective check300s, training600s per arm, free readout450s per policy, controlled continuations300s per policy, service readiness900s aggregate. These ceilings sum6450s, leaving450s for orchestration within work. No stage extends the shared deadline. Inference services release before optimizer jobs take the same GPU. Preserve partial corpus/readouts and unrun NULL coordinates.

Budget rationale is an extrapolation, not a measurement: prior16-example capture needed328s for48 actual child calls; the proposed32 examples use80 actual child calls before any optional repair, around1.67× that child count. Prior four-update16-example action training took49s;32 longer corrective targets/prefixes may cost several multiples. Observed complete-study readouts were approximately145–150s per16 endpoints with four workers; the generous caps permit32 free episodes per policy plus16 controlled continuations. The first-eight measured probe overrides these estimates. Do not automatically scale to64 examples within the same acceptance.

Promotion requires a paired gain in strict correctness on new query compositions **and** increased executed scope-correct reduction, without merely format cleanup or replacing map errors with unchecked fresh child calls. Report any regression on the fixed prior compositions. If controlled continuation improves but free roots do not reach/use the state, prefer Option B or a separately evidenced initial-policy intervention. If scope-action loss falls without either behavioral improvement, retire the specific target construction instead of extending epochs.

## Concrete implementation seams, not implemented here

The existing complete-SFT capture.py assumes two scripted root calls and one scalar observation; its scalar_from_prefix cannot simply be reused for map/error prefixes. Option A needs a bounded authored producer sequence of one or four decisions, then a corrective tool action and authentic final: three or six root decisions, while forwarding all c32 calls unchanged. Generalize the counted capture state machine and independently re-render each selected prefix; keep raw authored-versus-actual physical request provenance.

Existing learning.py requires exactly two turns and pairs first action with terminal at weights1/0.1. Do not mislabel a corrective program as “terminal” or let that hard-coded coefficient survive. Store explicit producer/corrector/final roles and select only the declared producer or corrective current-action row for each arm, using the existing per-example loss/mask/optimizer/checkpoint machinery. Source and transformed-code hashes, native image/runtime paths, credential preflight, corpus identity, outputs, seeds and all split memberships must be frozen in a new sidecar/READY before launch. The existing fresh recovery output namespace is not reusable.
