# When does keeping answers attached to records matter to a final answer?

September9,2026,08:08UTC. An exploratory interpretation and ranked follow-up,
not an accepted run or revision to active training. No new model outcomes were
generated for this note.

## What changed in the evidence

The completed384-call identity study confirms a strong item-correspondence effect
after removing numeric overlap. But its category-count diagnostics also show an
important difference: a permutation can preserve the number of each label while
attaching those labels to the wrong records. The ordinal condition with overlapping
numbers often did just that. Removing overlap improved its item accuracy while
worsening some category-count errors. This is not a paradox or a score repair.

Suppose the records are Alice's people question and Bob's number question. The
correct labels are people, number. Reversing them preserves the total of one
number question, but incorrectly says Alice asked it. A global count and a count
conditioned on a record's owner ask different questions. This is an illustrative
two-record example, not a traced model execution or proof of prevalence.

Therefore the current item-labeling and root-count-training gains are promising
but not yet one demonstrated causal chain. Do not claim that exact label coverage
is logically required by every count task, penalize cancellation retrospectively,
or replace the frozen strict-answer RLVR reward with a process-preference reward.

## Prioritized next comparisons

1. Complete the accepted helper-uptake96 test. A better returned representation
   cannot help if the coordinator never asks for it. Actual physical child calls
   and use of subsequent records matter more than a root-written helper log alone.
2. Complete the preparing child-role16 pilot. A clear local task may prevent
   costly package/search loops before adding a new API or changing weight training.
3. Run a small query-sensitive planning screen from the already checked candidate
   source pool: user-specific versus global counts on the same128-record files.
   Compare a fixed classify-all program, a deterministic filter-when-relevant
   program, and a free root. This measures the actual child-assisted opportunity,
   not an oracle-label upper bound described as achievable model performance.
4. If API uptake works, design a separately frozen correspondence-sensitive
   end-to-end comparison using user-specific counts or cross-user joins. Hold
   child request texts/weights/scoring fixed wherever feasible and record adaptive
   trajectory differences. Do not silently force helper use or change decoding
   along with a purported pure return-parser intervention.

The query-sensitive screen's useful plan really differs: one specified user's
eight records can be classified after cheap metadata filtering, while a global
count concerns all128 records. Both still allow classify-all; the potential gain
is task-sensitive accuracy/cost, not a proof of arbitrary decomposition. The root
may classify text itself, so child-call counts alone are not a semantic-work meter.

The feasibility proposal lists48 logical episodes. Its two deterministic programs
are identical on global questions. A prospective implementation could collect
those eight identical global baselines once and reference each in both comparison
tables, yielding40 distinct executions. That is transparent shared evidence, not
two independent samples; paired statistical bookkeeping must retain the shared
dependency. Decide this before execution, not after seeing duplicate outcomes.

## Training decisions depend on the screen

If the free root can execute the task and has mixed rewards but fails to use cheap
filters, a short query-varied root RLVR run is justified. Compare terminal exact
reward first with a separately declared cost-aware objective only if a real cost
tradeoff is present. Do not add a coverage certificate as a hidden success rule.

If it already filters well, test new query/metadata combinations or longer files.
If it fails the interface, first establish a usable instruction or a small varied
SFT curriculum. If local classification dominates errors, root-only RLVR alone
may have little headroom. Preserve the result and pivot rather than running a
larger predetermined training grid.

No claim of novelty for filtering, joins, IDs, role specialization, or generic
model–harness co-adaptation. The candidate contribution is an experimentally
grounded account of when local ability survives the route to a final answer.
