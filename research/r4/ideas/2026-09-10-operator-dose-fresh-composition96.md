## Exact question family

Common input is the unchanged native coding-role/file-only contract with id/user/text/weight, same category definitions, API/tool inventory, recognized optional-child transport/grammar and c32 child. No evidence map, new loader, aggregation helper, example, output grammar, reasoning hint, mandatory children or mandated batching. Preserve existing interface assets exactly; only context/query and prospective metadata change. The root chooses its widths and number of calls. Every question ends with the existing strict `Return only Answer: N` scalar contract.

All six use **all records, regardless of which user owns them**. Users are exactlyu0,u1,u2,u3, four records each. CategoryA cycles human being/entity/location/numeric value twice across context ordinals0–7; categoryB is the next category in that fixed cycle, hence A≠B. Assignment does not inspect labels. For contextordinalc, A=cycle[c mod4], B=cycle[(c+1)mod4]. The semantic meaning of question category is unchanged.

| Query | Exact intended instruction, with A/B substituted literally |
|---|---|
| P1 count | Count records whose question category is A. If none qualify, return0. |
| P2 distinct | Count distinct users having at least one record whose question category is A. If none qualify, return0. |
| P3 weight | Sum visible weights of records whose question category is A. If none qualify, return0. |
| C1 threshold | For each ofu0,u1,u2,u3, consider the sum of weights of that user's records whose question category is A; use0 if none. How many users have this sum **strictly greater than5**? |
| C2 maximum | For each ofu0,u1,u2,u3, consider the sum of weights of that user's records whose question category is A; use0 if none. Return the **largest of the four sums**, not the user's ID. |
| C3 cross-category | A user is eligible if at least one of that user's records has question category A. Sum weights of records whose question category is B and whose user is eligible. Count each such B record once. If none, return0. |

These statements define the requested answer, not Python algorithms or demonstrations. All-scope primitive controls deliberately remove ambiguous intersection wording; distinct-all is already a previously tested operator/scope transfer cell. This is not exact byte replication of old questions and not a newly trained curriculum.

Host oracle is deterministic: for each useru let S_A(u) be the sum of observed public weights of gold-A records. P1 counts gold-A records; P2 counts users with gold-A records; P3 sums S_A; C1 counts S_A>5; C2=max over all four S_A including zeros; C3 sums gold-B record weights for users possessing a gold-A record. This host code is evaluation-only, never shown to root or child. Independently verify against an alternative literal enumeration on authored edge cases: noA, noB, exact threshold5, threshold6, multiple A/B records per user, absent qualifying users, ties and repeated eligible users. Canonical formulas and source label mapping freeze before outcomes.
